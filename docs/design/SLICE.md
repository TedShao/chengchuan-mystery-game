## 前端要换掉的是操作结构

旧主结构是桌面 → 打开编辑器 → 填写 → 提交 → 等评价。新主结构改为：

**一个具体来信 → 找到它指的页面 → 比较两个视角 → 进行可撤回或可说明的干预 → 回到原入口发现改变。**

电脑仍在，但前十分钟默认只打开浏览器和企业聊天。文件、邮箱、表格、PPT、便签与摸鱼从任务栏可访问，不用它们拦路。没有调查作用的软件不加教学，不要求模拟完整 Office 才能推进。

```text
┌ 浏览器：〈 后退 〉    [课程接待] [客户看到的页面] [+]       收起 ┐
│ 地址 / 所属站点 / 页面日期                                     │
├───────────────────────────┬───────────────────────────────┤
│ 当前网页，沿用它自己的导航  │ 自选并排页；不自动标红“矛盾”     │
│                           │ 来源、版本、访问路径可追溯        │
│ 会话 / 详情 / 名片 / 回执   │                               │
├───────────────────────────┴───────────────────────────────┤
│ 企业聊天  邮件  文件  便签  …       仅显示实际新消息的通知      │
└───────────────────────────────────────────────────────────┘
```

- **网页而非悬浮卡片展览：**课程门户像面向学员的服务网站；内部接待台像列表与会话；远桥页面像另一个品牌的服务入口。每一页有归属、标题、正文、合理返回路径。
- **入口可识别：**普通链接下划线、访问后变色；按钮用动作命名。非交互广告不做假链接。未提供的栏目写明不可用，不能点击后无声无息。
- **可比较：**“在旁边打开”保留两边滚动位置；也能单页切换。对照内容由玩家选，不自动把答案两页配好。
- **可重访：**保留标签、后退、最近访问；浏览器内部地址仅在游戏路由中解析。模拟域名用保留域 `.test`，不要求玩家打开现实公司站点、拨真电话或输入个人资料。
- **可带出处：**选中一条消息可“引用到便签 / 发给同事”，生成来源卡；没有收集完成率或“关键证据”金标。
- **可知动作是否发生：**草稿、待交接、已发送、已读、被接手分别呈现。动作回执写变化对象和范围，不弹“推理正确”。
- **自由办公不抢注意力：**文档可自由写，表格可操作，摸鱼可回原页面；离开主线不自动触发坏结局，也不弹催办十次。新片段无需它们产生任务奖励。

界面约束依据 game-ui-ux：布局用弹性容器；窄屏并排变标签；焦点随弹层进出恢复；ESC 关闭预览不提交；Tab 可遍历；状态有文字不只靠颜色。动画与内容事件绑定，支持减少动态效果。以上是待实现规范，本轮未做分辨率或键盘运行测试。

普通搜索无密码：支持姓名、日期、标题与正文词语，结果保留来源片段；同名结果可以按系统筛选。没有结果时给出搜索范围和可修改查询，不判“答案错误”。关键材料同时有业务链接入口，不能只有一个作者预设词能找到。输入“缅北”不凭空生成一份犯罪名单。

本幕可形成两条交叉路线：`客户引用 → 代班详情 → 待发依据 → 接替回执`；或 `本人名片 → 停用 → 客户视角变化 → 原转介页 → 询问安排者`。第三种玩家可以先问人，省去已经得到可靠回答的步骤；游戏不要求把两条路线都打卡。

## 开场：先让人处在一件事里

不做人物卡轮播，不做八步强制教程。进入前只给短定位，可随时重看：

> 待业三个月后，你进了澄川。  
> 今天是第 47 天。你在“知禾学堂”发课程资料，处理学员遇到的小问题。  
> 这是你第一次收到罗青关于课程以外的留言。

电脑恢复到昨天的接待台，能看到自己补发过的播放入口。头像是自己，签名是“学习助理·林见”。右下角只有一条罗青的新消息。**身份、业务、自己做过什么都在同一个界面中出现。**

最低限度的操作教学采用一次可关闭的动态演示：通知到达 → 指向通知 → 点击后收起演示；引用消息被打开时，来源栏短暂展开。只教“怎样看引用及返回”，不把“哪个证据推翻哪个人”作为教学。

关闭全部指引后，新消息、链接和来源标签仍在。可按需打开“操作帮助”，解释软件按钮；它不列调查顺序。如果玩家没读通知直接探索，旧课程会话和代班列表仍可成为入口。

## 五个场景，不锁点击顺序

### 场景 1：她找的是谁

玩家目标是回应或查看找自己的消息。可以直接打开昨晚引用、回看旧帮助、点自己的名片、先问同事，也可以先摸鱼。

罗青不说“你的账户一定被盗用了”。她只认为还是这位熟悉的助理在回复。玩家若直接告诉她“昨晚不是我”，她的合理反应是：“那今天这件事，谁能给我个准话？”有引用时她能指回那句话；没有引用时系统可让玩家选择澄清哪条消息。

**可观察变化：**她是否仍把承诺算在林见身上、是否要求接待人说明。不是好感加减。

### 场景 2：小雨没有否认

问小雨昨晚的消息，她直接说：

> “昨晚是我回的。她认你这个头像，我没换。”

追问是否真的处理：

> “我把申请给周衡了。他说今天有人接。我没拿到结果。”

玩家拿旧的课程退款经历质疑她，她才谈那一次，不主动甩出退款教学：

> “上次退的是课钱，我能在订单里看见。这次我看不见。”

这段不能成为固定三连对白。玩家先停用名片，她先处理交接；玩家已经问过发送人，她后续不再重新交代“昨晚是我”。问两个问题按两个对象分别回应，不能只命中第一个词。

**新问题：**小雨知道自己发了消息，但她拿什么相信项目会处理？玩家能从队列附件自己核对，也可直接请周衡拿出依据。

### 场景 3：试一下他说的边界

不出“盗号 / 普通代班 / 公司诈骗”三选一答案题。允许玩家用实际动作表达判断：

| 动作 | 操作前能预见什么 | 实际改变什么 |
|---|---|---|
| 查看客户视角 / 名片历史 | 只阅读，不发送 | 获得不同视角，不自动让 NPC 起疑 |
| 向小雨询问某条消息 | 只让小雨知道这次疑问与所附内容 | 小雨承认或解释自己的行为；不能代周衡证明 |
| 停用本人名片 | 后续不再以林见名片发送；已有消息保留；当前会话需接替 | 原署名待发消息被挂起；周衡收到“需更换接待”的业务通知 |
| 给罗青发限定说明 | 明确列出罗青为唯一收件人；预览实际内容 | 改变她对昨晚承诺归属的理解；不让周衡自动知道 |
| 问周衡处理依据 / 要求接替预览 | 周衡收到疑问与选定引用 | 他提供预约；可提前看到接替安排，不必先触发某一“正确”剧情 |
| 暂不接手 | 不承诺项目结果；可保留自己已参与的会话历史 | 转交周衡；取消属于玩家的跟进动作，保留客户下一次实际消息 |

停用名片后周衡可以回：

> “行，你的名字拿掉。她这边我找人接。”

随后真的改为公司或远桥身份，更新待发项和交接预览。**让步之后的动作才是戏。**不加“你最好别多管”的廉价威胁，不用音效宣布他是坏人。

### 场景 4：回到刚才那一页

玩家回看原转介入口，或收到已发生的交接回执。林见的名片确实停用了，原先的客户会话却接上了远桥服务；内部回执显示安排由周衡确认。

若玩家向项目转接时只附一条“申请仍待处理”，项目摘要只出现这条；未附的个人质疑不传播。玩家可比较这一变化与“课程方不参与项目安排”的页面声明，也可直接问周衡为何能指定另一端的接待。

周衡的解释是“我们只是帮她联系”，不是承认共谋。玩家可以接受普通外包解释，也可以要求区分“安排了人”和“核实了结果”。这两者会改变实际发给客户的说法。

**观察目的：**玩家是否主动回去看，是否能说出一个更具体的新疑问。没有回看的人不会被自动塞一段侦探总结；回执只说明交接，不替他做结论。

### 场景 5：这件事能不能到此为止

玩家通过“结束这次交班”推进事件，不用浏览页面次数充当时间。按钮旁标明将执行哪些待发项；可以回去改，也可以让主管接手。没有实际发出的草稿不算承诺。

| 此刻的实际状态 | 结束交班后的事件 | 留给玩家的问题，不显示为任务 |
|---|---|---|
| 保留名片、允许原转接话发出 | 罗青仍把林见视为担保接待；下一次追问先找他；项目接待按原计划进行 | 我的名字在帮哪一种承诺维持可信？ |
| 停用名片，未向罗青说明 | 新身份接续；罗青仍留有旧承诺，询问“现在换人，昨晚说的还算吗” | 撤下名字解决了谁的问题，留下了谁的问题？ |
| 私下澄清但允许安排联系 | 罗青知道代班和未知结果；要求远桥自行确认；接待方收到的是她同意转交的要求 | 另一端能给独立结果，还是只重述公司摘要？ |
| 拒绝本人参与并要求暂不转接 | 本人待发项取消；周衡决定后续另约，必须先发明确通知；本幕不模拟客户已被说服 | 他为何还要促成这次联系？ |
| 向客户及周衡同时发送尚无依据的犯罪指控 | 对方要求说明证据；周衡以避免继续对外发送争议承诺为由接手这次会话；旧参与记录仍保留 | 哪项事实支持指控，哪项只是推测？ |
| 只把未经核实的指控私发给罗青 | 她要求出处或暂停透露资料；主管不知道该指控，不触发其权限反应 | 如何修正自己的判断并重新获得对方配合？ |

结果页只是当前会话与发送记录，不做“好结局 / 坏结局”评分。允许玩家在此停止；继续兴趣必须来自正在发生的事。这个片段不给境外定位、不发赴境外邀约、不新增下一章待办。

普通询问“为什么你能安排远桥的人”、附事实的限定说明，以及员工私下质疑都不自动触发收权。边界是**实际向谁发出了什么主张**，不能把“主管被问烦了”做成统一惩罚。拒绝转交只取消玩家控制的新发送；周衡如要沿既有项目联系方式另行联系，须显示新安排，不能把拒绝偷偷变成玩家同意。

## 对话与状态：可观察合同

前端负责显示，事件记录负责事实，角色知识只由实际接收推导。自由输入暂不承诺通用语义理解：主要调查靠选择**对象 + 动作 + 引用**，例如对这条消息询问发送人、用途或依据；选择的是做法，不是正确答案。可自由记笔记，普通聊天可保留。含糊输入先问“你说昨晚这条，还是今天待发的？”而不是误触发剧情。

| 事件 | 更新 | 明确不更新 |
|---|---|---|
| 阅读 / 并排 / 本地便签 | 玩家访问历史与自己的记录 | 同事知识、怀疑值、发送队列 |
| 向某人询问，附材料集合 A | 该人的收件记录与本次问题上下文 | 其他人知识、未附材料、任何待发项 |
| 发送说明 | 指定收件人的历史；对应信念变化 | 没收件者的反应 |
| 停用名片 | 本人身份后续不可用、相关待发挂起、主管收到业务通知 | 擦除旧消息、泄露私人说明内容 |
| 主管接替 | 按已知信息建立新的待发项与交接关系 | 把玩家草稿偷偷发出 |
| 执行交班 | 只发送当次已明确列出的项目，生成唯一回执 | 阅读次数推进、重复发送相同事件 |
| 改口 | 新说明关联原消息，更新实际收到者的认识 | 撤销已读事实、替收件人“失忆” |

追问规则：

- 同一事实重复问：保留已回答内容，简短指出没新增结果；不重新播整段背景，也不自动惩罚。
- 反对“我没说到账”：若玩家引用的是“明天处理”，小雨回应这项措辞造成的期待；不把否定误判为玩家接受安排。
- 同时问发送人和处理依据：逐项给已知答案；她只能为自己发送负责，处理依据指向现有预约，而非凭空生成新证据。
- 先误指盗号再改口：曾收到指控的人看到更正；只读过本地笔记的人不存在。客户可能继续要求具体接待人，不回到初次问候。
- 任务结束问旧事：回答已完成的交接与仍未知的申请结果；不能重新创建同一交班任务。
- 连续点击停用 / 结束交班：幂等，当前状态可见；重新启用名片是独立明确动作，不因聊天“好吧”自动恢复。
- 人物可拒绝承诺或资料请求；拒绝理由来自角色目标与当前信息，不由隐藏好感条决定。

## 动态反馈与删减清单

一次行动显示一处主体变化，加一处简短回执。例如停用名片后，名片灰显并标“停止用于新回复”；待发项显示“原署名已不可用”；主管的新消息是后续事件，不再叠全屏恭喜。

动作演示由真实状态结束，玩家已经自行完成则不再播放。高亮只指入口或当前焦点；已读材料不持续闪烁。录音/视频将来若使用，必须有字幕、可暂停回看；本幕不依赖音频识别或 AI 生成片段。

| 旧设计 | 新处理 |
|---|---|
| 开场先读人物说明书，再选工作内容 | 登录即遇到一位认识自己的客户；岗位由已做过的小事交代 |
| 八步教程按进度条推进 | 一次通知与来源操作演示；之后按需帮助 |
| 下拉选出唯一正确汇报措辞 | 对具体页面、消息和接待身份采取行动 |
| 完成审批后自动发下一任务 | NPC 继续处理自己的业务；玩家可回看实际后果 |
| 补齐所有软件菜单当作重构成绩 | 先实现浏览、比较、引用、接待变化；其他软件保留自由入口 |
| 日志写“可疑操作”、线索涂红 | 普通业务字段；异常由前后事实关系产生 |
| 同事复述刚发生的系统操作 | 只在有新要求、解释、拒绝或关系变化时回复 |

## 作者纸面排演：已经改过什么

方法：先固定 STORY 真相，再按下列不同顺序检查可见信息和后果。**这是知情作者的反证走查，不是新玩家盲测；只验证可行性，不验证好奇心。**

| 路线 | 原方案会坏在哪里 | 本稿已落实的修订 | 仍需真人观察 |
|---|---|---|---|
| 不读背景，先打开罗青引用 | 不知道知禾是谁，昨晚身份似乎是软件 bug | 岗位定位只三句；原帮助、名片、实际经办人各有归属 | 能否自然点来源，而非等任务按钮 |
| 不看详情，直接问小雨 | 若必须收齐材料才认，人物像锁 | 小雨当即承认；不强迫重演“盗号调查” | 承认后是否仍想查用途 |
| 开始就停用名字，拒绝接待 | 会丢掉全部会话，剧情卡死；或强迫恢复身份 | 保留自身历史与交接回执，主管另行接续，玩家不再是经办 | 是否只想退出；不能把退出算测试失败者不认真 |
| 接受“普通代班”，不核实 | 可能只能给错误评价，实际事件一样 | 原名片真的发送，后续追问归到玩家；收件与责任明确 | 是否理解是自己的允许导致，而非系统暗害 |
| 只看转介页，提前质疑公司关系 | 被要求先补完盗号线 | 可直接问周衡并取得接替预览，绕过发送人支线 | 普通外包解释是否过于充分 |
| 仅转客户原话，没附自己质疑 | 原来容易让同事全知 | 回执只能携带那条内容；收件人不评论未收到的指控 | 是否能从界面看懂范围 |
| 私发错误指控，再向罗青更正 | 原来可能无端触发主管生气 | 主管没收件不变；罗青更新认识但保留原质疑 | 更正后对话是否仍自然 |
| 公开指控后改口 | 一句道歉完全清空后果，或永久锁死 | 更正送到原收件范围；已接手不自动撤销，可请求参与后续 | 能否理解信任和操作权是不同问题 |
| 不看客户页面，只看交接 | 可能读到一个编号就等于“破案” | 回执仅证明安排；保留普通外包解释，原转介页能后补 | 是否愿意主动回看 |
| 重复发送、反复停用、关闭后重开 | 会刷消息、改状态、重复触发处罚 | 相同事件一次生效，历史保留；重新操作需要不同明确事件 | 运行期幂等还未测试 |

修订后 G2 的作者结论：两条核实路径和误判恢复路径可排演，仍有“只是账号管理”的体验风险。未到 G3；不得把这张表转述为“完整试玩通过”。

## 下一次如何证伪

使用同一份材料和同一故事，比较“只读回执重建已经发生的接替”与“玩家亲自停用名片并观察接替”两种纸面呈现；其他线索、人物、阅读量尽量相同。实验合同维护在 [H001](../experiments/H001/game-design-hypothesis.json)，不再测试已经退出本轮中心的答疑会共享冲突。

不给玩家“去查公司关系”的任务。观察他第一步想做什么、停用后是否回看、能否区分代班与背书、下一问题是否来自已见事实。结束才问：“现在你认为发生了什么？如果继续，你想验证什么？”

若只想撤名字、读回执像看后台日志，或只能说“主管是坏人”，先修改本片段；不靠添加境外 IP、密码、绑架或新文件提高刺激。若玩家不在意主角身份，这个前提可被推翻。

本轮交付是两份相互一致的设计稿和一次有限参考体验。真正尚欠的是陌生玩家在不看答案情况下的行为证据，以及随后最小原型的实际交互验证。
