# 当前计划

唯一任务与状态入口，2026-10-21。本轮完成文本重建和清理；不以“文档齐全”宣称体验已经成立。

## 已落地的文本范围

- 用户确认公司方向、境外诈骗与受控真相、主角被骗出境的结局尺度。
- STORY 补齐公司主营业务、人员分工、动机与知识、完整五段故事、六层推理设计、结局条件。
- SLICE 补齐开场可见材料、八场行动与反馈、十五条非预设路线纸面检查、陌生玩家测试方法。
- INTERACTION 补齐动态操作教学、软件职责、判断表达、收件边界、暂停/退出/改口、重复操作、存档和无障碍要求。
- 清除旧设计、研究、实验、试玩文本与历史稿导航。保留程序本体，不把任何旧剧情当新稿依据。
- 更新 GitHub 文档分支与既有草稿 PR。提交结果以 GitHub 分支为准；这里不把准备提交写成已发布游戏。

## 接下来按什么顺序做

| 顺序 | 任务与状态 | 依赖 | 交付 / 通过或退回条件 |
|---|---|---|---|
| P1 | 新故事因果审查：作者检查已做，设定可信度待外部意见 | 当前 STORY | 优先看赵为什么愿谈、公司为什么在何时让步、坏结局为何仍可信。任何一处只能靠人物犯傻成立，先推翻对应场景 |
| P2 | 现实边界补核：待证据 | REFERENCES 的明确缺口 | 访谈招聘从业者或找到适用的一手依据；只核日常职责、回访权限和境外岗位包装，不把虚构场景声称为真实案例。不能验证则简化承诺 |
| P3 | 开场陌生玩家纸面试玩：待证据 | SLICE 可排演；P2 中影响开场的硬伤处理完 | 先自选路线再提问。观察是否理解工作、为何找林见、下一步想确认什么；如果只想办完投诉即停，回故事核心，不扩章 |
| P4 | 后半分场压缩与结局排演：待证据 | 当前 E–H 场已成稿；P3 支持继续 | 检查赵不配合、公司真停、只撤本人、早求助和岗位邀请撤销。确认每段新认识，不用更多同类文件补时长 |
| P5 | 工程复用和实现计划：未开始 | 文本可执行、体验证据支持，并有后续开发任务 | 对照 INTERACTION 清点旧代码可保留/重写/删除的模块、存档与入口策略；此时才确定实现清单 |
| P6 | 最小可玩片段、测试、发布：未开始 | P5 与开发授权 | 先做开场，验证知识/收件/改口/重复/访问性；同版本体验与技术检查通过后再决定发布，不直接扩整日 |

P1–P4 可以继续修文，不意味着现在批准 P5–P6 开发。没有真人参与时可继续因果审查和准备材料，但不能把“代理假装新玩家”标成陌生玩家证据。

## 当前最重要的一张任务卡

**问题：**家属接通陈平之后，玩家是否会主动区分“能说话”与“能自由离开”，并愿意追问此前回来的人的经历？

**范围：**SLICE A–D；不增加新人物或新事故，不展开后续章节代码。

**观察：**记录玩家自己提出的问题、接下来找谁、为什么找；直接问主管、拒绝、漏看和先找赵均有效。主持人不得建议调查方向。

**否决：**需要提示“去找赵”；只能靠角色自爆；玩家把暂停后续招聘当作陈平已安全且材料无法纠正；操作只是逐项点待办。

**下一动作：**准备从实际开场内容开始的纸面扮演并收集陌生玩家反馈。当前没有该反馈，不填写留存、用时或通过率。

## 不确定项怎样处理

| 问题 | 当前采用的文本处理 | 需要什么决定 |
|---|---|---|
| 陈平最终控制地点与对外泰国职位的完整衔接 | 作者真相确定缅甸受控；不写转移路线，不以技术定位破案 | 现实可信度核查；若国家包装牵强，可简化，但不偷偷改受控真相 |
| 赵返国与受到的压力 | 写清其发送推荐时想离开；具体获释条件不作为谜题答案 | 进一步审查是否过度概括受害经历；不编“推荐一人即可换自由”的交易规则 |
| 坏结局是否有说服力 | 前置岗位意向、三次可退出节点；警觉或停止合作后邀请撤销 | 若玩家仍感觉主角被强行降智，向用户提出删改支线，不硬凑结局 |
| 全篇时长、收费、上线平台升级 | 当前仅有开场目标时长，继续用既有免费 GitHub 工作方式 | 核心体验验证后再定，不用扩文档代替产品判断 |

## 完成一轮后只更新什么

在相关稳定文件修改结果，本计划改状态和下一项。新的真实测试出现时才保存一份与提交对应的必要记录；不预建空测试报告、不恢复旧实验、不平行维护 Issue 和另一个进度表。当前文档是候选实现依据，尚无生产就绪结论。
