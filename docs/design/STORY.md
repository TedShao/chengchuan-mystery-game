# 故事规范：还有谁在听

状态：2026-10-20，关闭指引纸面反证后修订。基线为 `b96fb90`，旧稿的“主动改金额—替客户申诉—等待结案”不再是主线。**本轮把原申请改为“已受理、等待出款”，把结果页的主张明确为“收款账户已入账”**；这是新设计，不冒充旧稿已有线索。未改代码，无真人盲测；玩家材料与排演见 [SLICE](SLICE.md)。

## 核心与取舍

唐雯开场前投入了 3,000 元并申请取回。取消的是今天的追加咨询，撤图不会取消她的原申请。同一笔申请的详情仍在等出款，所附结果页却已经确认收款账户入账。林见发现，后一个页面来自自己做的课程演示。主管答应停用，又在原组件工作区准备一个不用填写金额的替代结果页；它仍把“已受理”写成“已入账”，没有换来对应的付款依据。

玩家的问题可以从“是不是两个页面没同步”变成“为什么我们能替一笔还没有付款依据的申请出具到账确认”。主线操作是打开同笔原申请、检查自己交付的组件、试着保留来源的原意并观察对方怎样处理。任意改金额是可选反证，不是新玩家应该想到的动作，更不是通关钥匙。

**删去平台资金异议、人工关闭、请求暂停结案三个环节。** 玩家不必代理维权，主管也不替平台决定钱怎么走。唐雯可自行处理钱款，本片段不模拟其客服流程。没有申诉，不会自动补发客服拒绝来推进剧情。

## 公司与人为什么行动

澄川对外制作课程、运营社群并交付客户网站内容组件；知禾是课程品牌，远汀是公开合作的境外登记投资服务方。林见制作教学示例，许蔓把示例包装成学员经历，顾成掌握项目的发布和交付。公开合作关系和境外登记不作为犯罪发现。

作者真相：核心经营者知道远汀的虚假投资业务，既获客，也提供维持可信外观的内容。顾成知道 A17 不查款，为减少退出争议，把受理结果包装成到账确认；此刻先同意撤下出错入口，再准备保留确定口吻的替代页。他需要维持客户交付，不愿把“我们还没有付款依据”写给学员；同时还想让林见继续维护这套内容，眼下选择保留草稿、不公开争执，而非强行恢复。这个让步是本幕的人物选择，不是赋予新人全公司发布否决权。顾成不写明犯罪意图，玩家看到的是正常协作中留下的候选与来源。

林见想保住工作，也不想自己做的练习成为别人的收款证明。他能预览、暂停自己交付的内容，不能动账户或提款。唐雯要取回钱，愿意分享单笔申请，未同意继续投资或把所有隐私交给林见。她来找知禾是因为先前课程服务就由这里接待，不是突然把内容助理当银行客服。

| 开场 | 唐雯提供本案只读分享，说明自己未收到；两个页面主张不一致 | 她要知道该信哪个结果，不能替作者提出“改个假金额试试” |
| 发现或暂停 | 林见可从原申请、组件使用位置进入；暂停使结果入口不可用，不改变提款 | 公司参与了展示和确认环节；控制页面不等于控制银行 |
| 顾成实际收到问题 / 暂停通知 | 他把原入口保持停用，在同一工作区准备待发布替代稿：去掉输入项，仍显示“已入账” | 降低客户疑问、维持确定口径；只用他实际收到或随后主动查到的信息 |
| 玩家核对替代稿 | 原申请仍等待出款；候选稿的内容依据仍是该申请或原组件演示值，没有新的付款记录 | 不是修复数据校验；但缺少付款依据仍不能证明钱款最终去向 |
| 拒绝恢复 / 同意带说明版本 | 拒绝则持续停用；只同意“状态来自申请、到账待核实”，顾成保留草稿，未发布无说明的版本 | 让步不等于承认全部犯罪；未发草稿是意图证据，不能写成再次骗到客户 |
| 明确发布替代结果 | 仅在可见确认后使用该版本；重新暂停可停止继续提供页面，已发副本不能追溯抹除 | 错误选择有实际后果，可以补充更正；不制造客户追加付款或报复损失 |

原申请处理时间、浏览器读取时间、候选稿制作时间分开显示。刷新不制造新处理进展；看了一页也不会自动发送、发布或推进资金。无现实倒计时。

## 表三：线索、初读与核实

| 可见对象 | 初读可能解释 | 区分动作 / 证据上限 |
|---|---|---|
| 同笔申请“等待出款”与结果“收款账户已入账” | 同步慢、不同款项、字眼混用 | 回原申请核对编号与状态；即使两页同笔，也只能提出矛盾，不能断言侵吞 |
| A17 教学原件和实际使用位置 | 正常教学帮助被嵌入客户网站 | 从使用位置打开客户结果，核对固定发布版本；同样式或同域名不是同一业务的充分证据 |
| 暂停自己组件后客户结果失效 | 澄川维护外包页面 | 证明交付依赖，不证明公司控制钱款；不把一次 404 当揭底 |
| 顾成候选稿及其实际引用 | 可能在修错页、消除用户填写错误 | 开原申请与候选并排；观察等待出款如何被写成入账，检查是否补来付款依据；关闭输入框本身不证明犯罪 |
| 在隔离预览保留“教学演示”或原申请原话 | 合理纠正说明 | 同一结果在注明来源后意义改变；顾成拒绝这版仍保留无说明版，是具体交付选择，不等于证明银行没付款 |
| 自主改金额的查询 | 怀疑输入被直接回显 | 同编号不同有效金额仍逐项匹配，可否定核验承诺；这是可选更强反例，早停者不必重新上线取证 |

A17 仅是固定内容组件，不存在未披露的“预览用假数据、正式自动接银行”两套逻辑。固定发布版本与实际使用关系能在普通内容工作区查到；如果以后引入动态数据接口，这里的推理必须重审。候选稿的“内容依据”是编辑工作所需的引用，不是突然找到写有犯罪内幕的日志；引用本身不保证依据真实。

## 表六：本轮审查结论

| 被否决的设计 | 修订 | 尚不能宣称什么 |
|---|---|---|
| 新玩家自然会故意改金额 | 从两种正常页面主张进入，改金额降为可选 | 不能声称旧稿有充分测试动机；也不能保证新人会找到组件来源 |
| 拒绝申诉仍要等客服给结果 | 删除整段申诉 / 结案；公司行为在自己的交付中可观察 | 拒绝一切调查当然可以结束，不能保证所有人都继续 |
| 客户一要求就能阻止平台结案 | 删去该虚构权力；保留玩家自己交付的暂停 | 停页面不等于停资金、追回钱或保护所有客户 |
| 主管说“核验有问题”推动揭底 | 只让实际候选的来源、内容与发布决定说话 | 一句正常解释、隐藏输入或外包依赖均不足以定罪 |
| 为看后续必须恢复可疑服务 | 候选可隔离预览，停用持续有效 | 未发布只能判断意图；不给早停者补发伤害换强证据 |

这轮修订有更明确的查看理由，但“有矛盾”仍不等于“有兴趣”。需要观察陌生玩家是否从改错页转向追问公司为什么提供这种确认；若只觉得是数据质量问题，就不能把十分钟公司悬疑标为通过。

角色、公司、金额与页面均为虚构；只在模拟网页操作，不用真实身份、银行接口、付款或外部联系。境外登记本身不定罪，实际资金去向仍未知。
