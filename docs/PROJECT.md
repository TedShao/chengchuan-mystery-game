# 开发先读：项目边界与当前基线

维护日期：2026-10-20。本文管理开发边界，不充当剧本。

## 当前决定

**暂停按 v4 扩写和实现。当前选定《你的离线时间》进入纸面验证：客户收到署着主角名字的承诺，主角撤名或追问后，公司换身份继续接待。** 这次推翻转正汇报和答疑会主目标，保留的角色也已重写。新方向仍可被试玩否决；已经花过的工时不是保留理由。

用户希望的是现实向、以公司电脑为探索空间的悬疑推理游戏。自由办公提供可信环境，不能抢走调查的主体位置。AI、真实短信和电话暂缓；本轮不新增付费服务，不改变代码与部署。

正式发布基线以 GitHub Actions 的成功部署记录为准。文档合并、分支存在、代码可运行和产品好玩是四件不同的事。

## 保留、删减、推翻的判定

| 对象 | 决定 | 原因 / 触发条件 |
|---|---|---|
| 公司电脑作为主要交互空间 | 保留产品方向 | 是用户长期明确偏好；并不等于要复刻所有办公软件 |
| 自由探索与摸鱼 | 保留能力、压缩首屏 | 玩家可以离开主线；不必首分钟摆满功能与人物 |
| 收件范围、草稿隔离、发送留痕、改口保留历史 | 保留行为约束 | 它们使推理与后果可信，不绑定某个故事 |
| 真实案件研究 | 保留三份参考中的相关资料 | 用于检验设定，不照搬受害者经历，不把境外等同犯罪 |
| 转正汇报、反复修订审批 | 移出重构主线候选 | 已反复得到“像办公、不好玩”的反馈；除非能证明不可替代的调查作用 |
| 罗青、小雨、周衡等人物 | 可借用，非锁定 | 人名不能代替可见需求与对抗；可合并或删除没有独立作用的人 |
| v4 答疑会 | 推翻默认采用，重新竞争 | 取消接入易查明，恢复接入可能成为无代价最优解；后半场仍可能是主持流程 |
| 长篇背景、重复同事解释、自动下发待办 | 默认删减 | 删除后若人物与行动仍成立，就不应保留 |
| 全办公桌面、整日剧情、多套开场 | 暂保兼容，列入后续退役评估 | 本轮不动代码；新片段验证后再决定生产入口和删除路径 |

删掉不是否定当时工作价值。被替换内容退出当前树，Git 保留历史；需要借用时只提取必要部分，重新核对，不整份恢复成“最新依据”。

## 决策记录

| 编号 | 决定 | 依据 | 影响 |
|---|---|---|---|
| D01 | 不把 v4 当实施规范 | 用户指出冲突不足，并要求考虑删减、重构、推翻 | R01 必须包含一个不沿用答疑会的方案 |
| D02 | 技术通过不再作为扩章条件 | 旧版有回归记录，用户仍明确认为不好玩 | 体验门槛与技术门槛分开 |
| D03 | 只维护一个当前计划和两份未来实施规范 | 多代文件存在相互冲突的“当前版”称谓 | 退休稿只留固定 Git 链接 |
| D04 | 先处理一个片段，不做整站大翻修 | 核心冲突尚未验证，全面重构会扩大返工 | R01—R03 前不开始 R04 生产重构 |
| D05 | 《你的离线时间》替代修稿 / 答疑会，进入纸面验证 | 两个骨架比较；参考游戏显示网页路径与二次解读可承载调查，尚无本作真人证据 | 下一项 R03；不改游戏代码与部署 |
| D06 | 前端围绕浏览、并排、引用和实际接替重构 | 旧版任务串被反复反馈像办公；参考的搜索前置锁也可能造成无目标探索 | 先验证动作动机，Office 菜单不再决定主线 |

这些决定不要求每次操作再向用户请示。既有授权内按验收证据推进；只有方向超出用户边界或缺少必要的真人证据时，明确说明差什么，不能替用户批准或伪造验证。
