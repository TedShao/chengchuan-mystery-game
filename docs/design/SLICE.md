# 网页片段：还有谁在听

状态：2026-10-20，对 [b96fb90](https://github.com/TedShao/chengchuan-mystery-game/tree/b96fb9057fb9ecbd50c3f00bd6144b987e632325) 关闭指引纸面反证并删改。以下排演由知道底稿的作者限制可用信息进行，**不是陌生玩家实际体验**。先记录旧稿停止点，再列新稿；没有把修订补入旧版后宣布旧版通过。未改代码、未运行网页，不保证十分钟时长。真相见 [STORY](STORY.md)。

## 旧稿：不替玩家预写“下一步当然要改金额”

纸面规则：只见当前屏幕；没有调查清单、荧光框、试错指令或主持人补话。每步允许选择最普通的做法，并在缺少动机处停止；下表中的选择是反例排演，不是用户行为统计。

| 非预设路线 | 当时可见 → 合理动作 → 旧稿反馈 | 停止点 / 判断 |
|---|---|---|
| 信正常查询 | 唐雯说未收钱 → 按她的真实 3,000 查询 → 显示匹配、已付 → 问是否延迟 | 没有新异常促使输入另一个金额。把下一步写成“固定编号改金额”是在给作者答案找动作 |
| 先停组件 | 从已知教学稿停用 → 客户链接不可用 → 隔离预览仍有演示 | 预览演示正常返回成功不能自动证明生产不查款；需要明确固定版本关系。下一步可能只是通知项目修错页 |
| 直接问主管 | 询问用途 → 顾成说可能误接、同意停用 | 合理解释暂时解决眼前问题，旧稿没有理由强迫玩家以技术测试回应；主管态度不能当罪证 |
| 拒绝申诉 | 发现问题 → 不替客户办资金异议 | 旧稿最强的“明知后结案”不发生；让唐雯自动完成并回报，只是把必做投诉转交 NPC |
| 技术型探索 | 自主输入不同金额 → 确认两次匹配冲突 → 暂停 | 功能反证成立，但不能拿这种路线代表新玩家；后半仍像提交 bug 后等待客服处理 |
| 完全退出 | 撤图撤约后不再查 | 可以合理结束；不能据此断言所有人无聊，也不能写一条新事故把人拽回来 |

六表反查的证据等级：真相表中的投入和不查款为 **explicit**；认知表中顾成未收反例不知玩家发现为 **explicit**；线索表的互斥结果为 **explicit**，自然去试它为 **missing**；动机表的维持交付为 **strong inference**，收到反例仍机械结案的具体理由为 **weak inference**；场面表从撤约跳到测试、再跳到申诉的自发动机为 **missing**；验证表所谓“可关闭结案”是作者规定，不是可信制度依据。旧稿能构成软件缺陷与纠纷，不足以证明公司调查体验成立。

## 本轮删改

- 删“必须故意改金额才能发现异常”；保留为玩家主动提出时的可选反证，无额外积分或隐藏通关条件。
- 删资金异议页、受理席、一次人工结案、暂停结案；不再替学员办理客服流程。
- 改原申请为“已受理、等待出款”，结果仍声称收款账户已入账。**这个差异是本轮新增，不属于上表旧稿。**
- 把后续压回原组件：主管准备怎样替换它，替代稿是否真的有比原申请更多的依据。用同一工作区的版本与实际发布结果观察，不加秘密文件、另一个受害者或新软件。

## 新稿首屏与自然入口

> 你是林见，在澄川做课程内容，第 47 天。知禾的回放、课件和交互示例归你，社群是许蔓在管，项目发布找顾成。

唐雯已有服务会话：

> “今天的电话取消吧，不加了。前天申请取回的三千还没到。这边还在等出款，点进去又说到账了。陈姐说她昨天就到了，我这笔该信哪个？”

随消息只有本案只读分享卡与她引用的陈姐图片。卡可打开“申请详情”，其内有“查看结果”链接；不是三份必须读完的附件。她已经许可查看这笔，不能由此查整个账户。

申请详情可见：`申请 3,000 元 / 已受理，等待出款 / 单号 TW-0417`。结果入口针对同一单号，正确金额查询后显示：`收款账户已入账 / 金额一致 / 尾号一致`。付款依据尚未提供。状态文字不靠颜色表达，两个标签可并排；刷新显示最新读取时间，但不伪造新的资金处理时间。

桌面最近使用中有林见上周做的 A17《到账状态说明》，含图与交互示例。没有“可疑线索”标签。所有普通办公与摸鱼入口保留，不需先写汇报。初读可以相信同步慢；玩家可先取消咨询、问唐雯、问主管、看自己的素材，或退出。

## 三处空间，不能把按钮变成资金权限

| 空间 | 普通可用操作 | 不能发生的事 |
|---|---|---|
| 既有服务会话 | 撤约、问来源、引用具体消息，向许蔓或顾成发送选定内容 | 私下预览、未发草稿不被读心；单问用途不等于授权对外联络 |
| 唐雯本案分享 | 原申请与结果之间跳转、只读查询、并排看，撤回许可后停止获取新信息 | 不登录银行、不改提款、不自动提出申诉；没有所有客户名单 |
| A17 原工作区 | 原教学稿、固定投放版本、使用位置、暂停、候选预览、明确发布或继续停用 | 无账户数据写权限；草稿与公开页分开，暂停持续有效，不自动偷换版本恢复 |

广告图可先解决：许蔓承认陈姐是运营角色、图片来自示例，实际撤图并停止追加联系。她不解释核验机制。唐雯不重复发“接下来请查公司”，原申请仍可返回，也可到此结束。

## 调查：是两个页面慢了，还是公司在制造确认

**先允许正常查看。** 回到同笔申请核对编号、时间与状态，是在解决眼前两页矛盾，不是测试系统。相同编号且未有新处理，仍不排除同步问题；主管说“可能接错，先停”可以暂时采信。不要在此给“已发现诈骗”提示。

**再核对自己做的东西。** A17 的普通使用位置能打开刚才的结果入口，固定投放版可与教学原件预览。显示教学说明后，同样的“成功”变回课堂示例。恢复说明只改变解释，不能单凭加水印证明正式系统没有真实数据；必须确认实际投放的是同一固定内容版本，未接另一套交易逻辑。这个关系来自自己的交付对象，不靠源码、密码或突然出现的审计日志。若玩家只看出界面相似，结论只到相似。

**暂停的反馈有边界。** 操作前显示“暂停此组件，关联结果页将不可用；不会更改申请与资金”。暂停后重新打开本案结果链接显示暂不可用，原申请仍在等待出款。它证明澄川维护该结果，不证明公司拿走了钱。旧版可隔离预览；没有已分享的结果，就不凭空恢复客户私信。

**改金额是另一条路。** 玩家若自行提出“是不是填什么都说对”，可保持编号不变改任意有效金额。新结果明确回显新输入且仍逐项一致，格式错误正常报错。这个反例支持核验不可信，但不改资金。没有同事建议输入假金额，没有专用“测试漏洞”按钮；不做它同样可以继续。内部演示的成功本身不是异常，要和其真实用途结合。

## 后续事件：主管的“处理”可检查，也可阻止

触发只来自顾成实际收到的用途疑问、具体矛盾，或内容系统发给项目负责人的暂停通知。仅打开页面不触发。他的第一次回应按信息而变：

- 只问谁管投放：“这个项目我接的。哪个位置不对？”未给对象不自动讨论唐雯的钱。
- 只停组件：“看见你停了。先别恢复，我把结果页另存一版。”只做通用候选，不出现唐雯的私密数据。
- 已收到同笔两种状态：“原入口先停。别让她来回填，我把申请结果单独放出来。”承认展示要处理，不坦白全部骗局。

这是他保交付的动作，不是给玩家派“请完成三步复核”。同一 A17 工作区出现待发布版本；玩家可查看，也可不参与。没有为了补线索而突然生成过去的秘密版本。

候选中输入框被去掉，文字仍是“收款账户已入账”。已有本案信息时，候选引用的“原申请”可以直接打开；仍是“等待出款”。没有本案信息时，候选只有原教学值，不能说它已针对唐雯作出确认。原稿、实际投放版、候选稿有各自名称和发布时间，不能混用。

玩家可在隔离预览中保留“教学演示”，或让正文只使用原申请原话；不用改金额也能看到，这样就不会再得出“已入账”。**这是对现有交付依据的核对，不是必须完成的一次文案作业。** 不保存、不预览、不发稿都不扣分，直接问依据或保持停用同样有效；不以写了指定句子授予发现。

若玩家问款项依据，顾成在已收到本案材料时可引用原申请：“我手里也是这张，你看。”玩家自己检查该状态究竟说了什么；不凭这句台词得出资金结论。若尚未获得本案信息，他只能问“哪一笔”，不能突然调出唐雯账户。若顾成另有真正付款依据，应允许验证，这份候选没有提供。

若玩家把候选的入账确认与原申请的不确定状态明确一起发给顾成，他查看后保留无说明的入账稿为待发布，不接受带演示说明的稿直接给学员使用。短回复即可：“带‘演示’的先别发。结果页也先留着。”随后界面保持两稿、原入口仍停用。**事实是他准备交付的内容仍超过依据，并非已经再次发给了客户。** 对方的选择使“修一个错链接”不再足以解释全部现象，但普通失职、等待新材料仍是可讨论解释，不能提前定罪。

玩家无需同意可疑发布来获取这层信息。主线问题变成：公司为什么在出具这种确认，真正的付款依据该由谁提供？若玩家只想维持停用，唐雯另行处理钱款，本幕可以结束。

## 实际选择与可见后果

| 行动 | 实际改变 | 没有发生什么 |
|---|---|---|
| 只撤图撤约 | 图片撤下、追加电话取消 | 既有提款未撤销，无新损失或新受害者救场 |
| 最早停组件 | 原结果一直不可用；可看原版本与之后候选 | 不需要恢复才能查，不因拒绝把别的版本偷偷上线 |
| 直接问并接受误接解释 | 顾成可处理展示问题；用户若返回可检查候选 | 接受解释不是坏结局，不自动授予反例或强迫追问 |
| 拒绝申诉、愿意自查 | 唐雯知道林见不代理资金事务；本案授权可保留或撤回；林见仍能查看自己组件 | 不代发投诉，不把 NPC 的客服遭遇当必达下一幕 |
| 拒绝恢复 / 只同意说明不确定性 | 保持停用，候选不公开，顾成没有得到对外发布同意 | 不会为了证明他坏而强行发出；此路只能判断准备交付的内容 |
| 明确同意无说明结果页发布 | 确认框展示版本、目标入口与收件范围；实际投放或发送后才能有送达记录 | 不因一句“知道了”“你处理吧”推断同意对客声明，不自动付钱 |
| 事后改口与更正 | 再停发布阻止新访问；已送对象收到明确更正才更新认知 | 不抹去已发副本，不把私人反悔广播给同事 |
| 完全不参与 | 停留在已完成的局部结果，继续自由办公或结束 | 没有全线真相保证、倒计时和惩罚事故 |

追问“那钱呢”不是发布许可，否定“我没说她已经到账”不应匹配成到账确认；同一消息同时问用途与拒绝经办，应分别回答已知用途并保留拒绝。同一疑问重问只补缺失对象或指出尚未新增依据，不重复造候选、通知或指控；先停再问与先问再停不能出现两个独立修复事件。

## 修订后按相同反路线复查

| 顺序 | 当前信息能支持的操作与判断 | 仍可能停止的地方 |
|---|---|---|
| 不改金额：先查原申请，再看结果 | 看见同笔两种状态 → 问主管 / 查自己的投放 → 保持停用 → 看候选是否依据原申请 | 可以暂信同步慢。不能写成新人必然继续；若无意核对候选，停在未明原因 |
| 先停，不保存截图 | 已投放版本在自己工作区可预览 → 原申请分享仍可读 → 看新候选与来源 | 可确认自己的交付；若唐雯撤回许可，不再取得新账户状态，只得有限结论 |
| 先直接问主管 | 顾成正常解释并处理 → 原入口停用 → 查看其实际候选，而非等他讲漏嘴 | 单听回复不算发现；正常补救确实会降低疑虑，不能强行写成可疑 |
| 拒绝申诉 | 不进入任何资金流程 → 自查自己作品 → 发或不发具体矛盾 → 决定是否恢复 | 无申诉仍有公司行为可核实；完全不想看自己的组件则可结束 |
| 只停、不发本案信息 | 暂停通知产生通用候选 → 看到其沿用教学结果 | 顾成不知唐雯资料；只能讨论通用组件，不能解锁针对她的明知判断 |
| 漏看广告 | 从同笔状态差异进入 → 投放关系 → 候选依据 | 不知道陈姐是运营角色也成立，不要求回头补图 |
| 误判后改口 | 把“公司拿走钱”收窄为“这份结果没有对应依据” → 继续停用或请求可核对来源 | 顾成只对收到的指控与证据回应；过度推断不变成怒气惩罚或额外损失 |
| 自主输入反例 | 可先否定核验承诺，再对照公司候选 | 这是合法捷径，不再是作者给全部新玩家指定的路线 |

复查结果：移除了必须猜到的软件测试和必须代理的客服事件；普通查看已有明确对象，提前停止与拒绝不再破坏公司调查入口。**尚未证明候选比较有趣**：它仍可能被理解成展示层错误与项目扯皮。下一轮若玩家只想“把页修好”，应继续删改这段，不增加另一场申诉或另一份文件证明严重。只记录实际提出的新问题，不把作者的问题当玩家动机；验证约定见 [PLAN](../PLAN.md) 与 [H001](../experiments/H001/game-design-hypothesis.json)。

## 参考游戏：实际走了哪些路

对象是用户给出的[新纪元电视台专栏](https://spectrum.shiroki-y2.top/neweratv.com_20051013_column.html)。2026-10-20 使用桌面 Chrome，选择纯净模式。未读攻略、未用源码取答案；完成的是下面这些探索路径，**没有通关整部作品，也未验证其完整故事或结局**。

| 实际操作与观察 | 对本作有用的判断 | 不照搬什么 |
|---|---|---|
| 从专栏阅读人物及节目背景，退到[存档查询](https://spectrum.shiroki-y2.top/webtimetower.html)，查询预填网址得到两个日期 | 网页给出可追踪的对象，玩家自己决定跨到另一年代；页面用途就是玩法 | 不把公司系统全部做成存档站；公司历史必须有业务上保存的理由 |
| 先选[2008 年](https://spectrum.shiroki-y2.top/neweratv.com_20080410.html)，看到关站通知，再查看[2005 年](https://spectrum.shiroki-y2.top/neweratv.com_20051013.html) | 不同版本形成问题，比任务列表先宣布“这里有异常”自然 | 关站本身不证明犯罪，也不照搬年代或停站情节 |
| 沿节目进入[财经页](https://spectrum.shiroki-y2.top/neweratv.com_20051013_finance.html)，当次页面只有节目横幅及通用导航 | 仿真栏目建立网站感，但入口可能没有调查回报 | 不为“整站完整”堆一排空链接 |
| 输入专栏主持人姓名尝试搜索，收到需先输入密钥的提示；之后该标签控制中断，新标签继续 | 本次没有从所读页面找到密钥去向；搜索前置锁是可记录的障碍 | 不将通用搜索锁在无上下文密码后。浏览器控制故障不能归因为游戏 bug |
| 从[新闻页](https://spectrum.shiroki-y2.top/neweratv.com_20051013_news1.html)点到[论坛讨论](https://spectrum.shiroki-y2.top/externaldata/digitalhome.com_content_it_2620.html)，读到数字和后续读法提示；按楼层、段落、去标点后的字序手算得到一句带威胁感的信息 | 日常聊天既是气氛，也能提供解读方法；发现后同一页面意义改变 | 这是作者手算解释，未获得游戏判定确认。现实办公室不凭空放密码诗，更不复制原谜题 |
| 从新闻进入[访谈](https://spectrum.shiroki-y2.top/neweratv.com_20051013_news_interview.html)，正文部分显示丢失 | 缺失的位置也能提出问题 | 不把所有关键证据都藏在“损坏数据”，更不靠故障特效冒充悬疑 |
