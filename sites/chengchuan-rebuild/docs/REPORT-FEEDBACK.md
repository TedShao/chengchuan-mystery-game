# 第一章工作案例：逐栏反馈与修改闭环

## 玩家可见流程

根据后续试玩反馈，三个工作案例现在默认使用下拉选择组织正文。每栏先留空，选择后显示实际写入草稿的完整句子；包括不同经办方式、不同结果范围和待确认的叙述。选择不会提交，也不会通知同事。玩家可切换「自由改写」，自写内容在下拉模式下显示为「保留当前自写内容」，切换和刷新不覆盖草稿。自由办公与文字软件编辑保持可用。

动态教学随当前模式定位选框或输入框。重发后编辑区改用最新已收到的反馈，不继续展示旧版错误。下拉稿与自由稿共用真实正文、发送快照及逐栏反馈。

实际发送后，周衡的回信分别列出「工作背景」「本人完成的工作」「结果」的反馈。已说清的栏目可以保留；待补充栏目说明尚缺什么，并提供「修改这一栏」和「查材料」按钮。材料链接进入真正的邮件历史或工作记录，定位对应往来；返回按钮回到正在修改的栏目。材料不会替玩家填写结论。

编辑区保留已发稿反馈，提示草稿是否已经修改。玩家可主动「检查修改」，但这只是本机检查，不发送、不改变同事知识，也不更新上一版回执。重新预览、确认发送后才生成新的已发快照与回信。教学第 8 步定位实际需要补充的栏目，不要求重写已清楚的部分。

## 判读范围与限制

暂不接入 AI。`report-review.js` 是适用于附件补发、课程改期、图表整理三个工作案例的本地规则解释器，不是通用语言理解。它使用分栏、分句、主体与收件人区分、动作与对象关系、反馈来源、否定与计划语气、引用归属、明确撤回与改口等条件，而不是凭全文出现某个关键词直接通过。

标题及资料来源不代替正文。引用中的「我」不直接计作玩家经办。可识别范围内的同义表达不需要固定答案；无法解释的表达会要求补充对象、动作或反馈来源，不直接宣判故事真相。广泛结论要求标明依据，引用结论不等于独立核实。明确尚待确认可以保留，不强迫玩家编造成功反馈。

仍可能无法识别复杂省略、反讽或任意口语，应根据实际试玩继续补充有针对性的关系测试。保守澄清优先于宽泛词命中。

## 状态约束

- 反馈绑定实际发送的版本，不能用未发送的新草稿倒改旧回信。
- 收到回信前不提前展示逐栏评审。
- 老存档缺少结构化反馈时，根据当时已发快照生成展示建议；不补发消息或修改原稿。
- 本地检查、查材料、教程确认均不推进剧情任务。
- 所有改动仅在独立重构项目及 5174 端口内生效。

## 验证

- `tests/report-review-domain.test.mjs`：乱填、词语堆砌、空正文、同义表达、部分完成、主体/收件人、否定、计划、引用、改口、矛盾结果、结论范围、三个工作案例及自由正文。
- `tests/report-feedback.cjs`：实际发送 → 逐栏反馈 → 定位原件 → 保留正确内容 → 本机检查 → 重发；旧存档兼容、教程定位及窄屏。
- `tests/first-lesson.cjs`、`tests/rebuild-opening.cjs`：教学和关闭教学的操作回归、预览取消、版本保留、自由办公。
- `tests/report-choice.cjs`：下拉教学、误选、部分正确、改选重发、自由改写互换、刷新保留与三个案例。
- `tests/chapter-one-probe.cjs`：关闭指引、口语汇报、复盘先于工作簿、追问凭证/作者/日期、索取旧记录、原邮件核对、更正共享稿、拒绝接手及保存下班交接。
