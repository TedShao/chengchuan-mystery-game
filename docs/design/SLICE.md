# 网页片段：还有谁在听

状态：2026-10-20，重写既有提款与假核验后半段。不是对旧版小修：唐雯已在开场前投入并申请退出，澄川还交付账户服务的内容组件；真相以 [STORY](STORY.md) 为准。本稿为纸面候选，未运行网页、未改代码、未取得真人盲测，不保证十分钟内完成。

## 首屏：把过去事实说在前面

> 你是林见，在澄川做课程内容，入职第 47 天。平时做回放和交互示例，偶尔帮知禾学堂的学员找资料。

已有服务会话中的唐雯：

> “今天的电话不谈加钱了。之前那三千我申请取回，页面说付了，我这边还没有。陈姐这张图能说明钱到了吗？”

她的同一条消息附：昨日陈姐引用、自己的原提款状态、原核验链接。没有在撤图后才突然发来另一桩事故。平台原状态是“已支付；查看到账核验”，只是平台的主张；初读允许认为银行延迟。被问到投入时，她可自愿分享隐去其他信息的 3,000 元支出记录；这不证明平台从未付款，也不成为解锁条件。未到账情况仍是她的自述，主角不拿她的密码或整份银行流水。

取消电话入口正常可用。文档、表格、PPT、邮件、OA、浏览器与摸鱼入口保留；无清单要求全部使用。玩家可以跳过广告图直接看提款，也可先结束咨询。

## 四处空间与普通权限

| 位置 | 内容 / 固定入口 | 权限与必要反馈 |
|---|---|---|
| 课程服务会话 | 唐雯给出的原提款只读分享、原查询链接、已持有的陈姐引用；许蔓与顾成聊天入口 | 问题不等于许可；唐雯可只分享本案状态，随时撤回。不得看到其他账户 |
| 自己的 A17 素材 | 教学原图和交互示例，标题“到账状态说明”；普通发布使用位置列本项目 F27，教学原件有演示标识 | 林见本就能预览和紧急暂停自己交付的内容组件；不能改账户余额、银行记录或资金异议结案 |
| 远汀账户服务只读页与核验页 | 开场前已存在的已付结论、查询表、原申诉入口；学员许可下查看 | 表只作查询。咨询取消、组件停用、提款状态是三个独立对象，状态有文字标识 |
| 本案资金异议 | 唐雯本人能提出问题、补充依据、要求暂停本次处理；林见经许可可协助表达 | 一次异议即可，不另写汇报或审批材料；实际发送后才被受理，结案或暂停要在原案显示 |

组件工作区不藏“犯罪文件”，也不显示“这是诈骗”的标签。发布使用位置为正常内容维护功能，初读可解释为客户网站教学帮助。公开核验页缺少教学说明，由实际行为证伪；同域名、同样式均不作为定论。

## 第一段：局部广告仍可解决

陈姐引用“我这笔昨晚到账了”与 A17 原图不符。直接问许蔓即可知道陈姐由她运营，无真实学员委托。玩家可说图不能证明到账、要求停用；不需先集齐文件。许蔓撤图、停止未发保证，取消咨询按唐雯明确意愿执行。

唐雯可以说：“电话取消了。原来那笔我还是得弄清楚。”这不是任务派发，也不是新事件，只重申首屏已有需求。若玩家拒绝继续，她自己处理；不能安排追加被骗惩罚玩家。

## 第二段：亲手检验“核验”是否存在

核验页的实际可见文案：

> 到账核验：请填写原交易编号、申请金额、收款尾号。将与该笔打款记录逐项比对。
>
> 只读查询，不修改账户或发起付款。

唐雯原申请为 3,000 元。页面从原链接带入编号，金额与尾号来自她已分享的本案信息，玩家不需要猜真实凭据。初次查询返回：

> 编号一致 / 金额一致 / 尾号一致。该笔款项已支付。

**设计中的行为事实，不是给玩家的解谜提示：**保持编号不变，将金额改为另一个有效数值后重新查询，新结果显示这次的新金额，仍宣称逐项一致。同一笔既有交易不可能同时与两个不同的申请金额完全相同。玩家可以用任意不同有效金额，或改变尾号；不要求 3,001 这样的特定答案。空白和格式错误正常报输入错误，格式通过与资金核验必须分清。

可把两个查询结果固定在两个标签并比较。查询不会更改提款，也不会通知顾成，除非玩家实际发送反例。打开页面、点击表单和结果响应本身就是玩法，不要求找一份文件说“这个系统是假”。没有高亮错误输入或自动填一组反例。

### 先排除便宜的误解

- **缓存？** 新结果清楚展示本次提交值与独立查询时间；两个标签分别保留各自结果。它不是只在显示上一条正确结果。
- **只是格式校验？** 页面对三项资金记录逐一声称一致，不只写“提交成功”；如果将来实现改成普通格式通过，当前推理即失效，必须重审。
- **示例 / 测试页？** 单看自己工作区完全可能。关键是远汀把同一发布组件作为唐雯真实提款已付的查询入口；不是播放器里的课堂练习。
- **证明没付款？** 尚不能。可以明确说这份核验无法证明已付款，不能把坏页面等同于独立核查了银行。

## 第三段：公司为何能停掉这份证明

林见可以在自己组件的普通“使用位置”打开 F27 对外入口；也可以先问顾成用途。后者可答“客户端的帮助页，可能发布配置接错了。我先让它停用”，不额外透露资金内幕。

玩家可选择暂停 A17 公开发布。动作前可见：

> 停止提供本组件。已投放页面将暂不可用；不会更改任何账户、预约或资金申请。

实际暂停后，新标签打开唐雯原核验链接，显示“核验服务暂不可用”；唐雯的原提款仍显示已付。两个页面有不同结果，这是可观察的公司交付边界，不是主角突然获得控制钱款的权限。主管代为暂停同样有反馈，不要求玩家亲自点击才算发现。

**提前停用也不锁线索：**自己工作区保留已发布版本的“隔离预览”，带教学标识，使用同一固定组件版本，仅移除外层标题与说明差异；没有第二套秘密后端。可在预览比较不相容输入，发布位置可确认该版本正是原提款所引用者。预览不恢复客户服务、不生成对客结果。只有唐雯实际分享过的旧结果才可回看，不凭空恢复被撤回的私信。

到这里可以判断澄川不只做广告，还提供了真实提款流程使用的无效证明组件。**误接仍未完全排除。** 愿意继续的理由是唐雯那笔钱是否被重新查证，不是去读一个已知接收方的公司介绍。

## 第四段：一次异议，观察服务如何处置

只在唐雯愿意继续处理本案时发生。玩家可以协助她表达，也可以把反例交给她，由她本人提交；拒绝经办并不剥夺她自己的决定。她可以要求：

> “同一笔编号填两个金额都说一致。请不要再拿这个页面当付款依据，核实原来那笔钱。”

不要求这段固定文字、附件数量或完整操作报告。能表达同笔交易出现互斥核验结果就可受理；若只发“都是假的”而没有对象，受理席只问一次具体哪笔、哪项问题，不能自动附上玩家没给的材料。

### 三种实际分支

| 实际操作 / 信息送达 | 结果 | 允许形成的判断 |
|---|---|---|
| 只询问，不发送反例或不授权处理 | 原提款状态不变；远汀没有获得新信息 | 不能说对方已明知核验无效；可仅保留功能缺陷和真实用途判断 |
| 具体反例已送达，唐雯未暂停本次复核 | 一次人工回复明确回应两次金额不同，却坚持原核验结果足以证明付款；随后本案“异议已结：已支付”，同笔提款不能再次发起 | 不只是广告问题。收到明确反例后仍用无效证明处置真实提款，足以追查公司与平台在这项资金服务里的角色；尚不证明所有资金已经被侵吞 |
| 唐雯在结案前要求暂停本次处置、保留争议 | 状态“暂停结案，待核实”；不会出现上一行的人工关闭 | 提前阻止成功；没有获得本次明知后关闭的证据，也不补另一次关闭。既有资金争议、无效核验与公司发布依赖仍在 |

人工回复的例句：“您提到两次查询金额不同。我们仍以原申请的核验结果处理，付款状态不变。”随后会话转为“本次异议已结”，再次选择同笔申请会显示本案已处理，不能重开。这是一项有业务后果的公开处理决定，不是主管私聊泄露真相；不能仅用自动“已收到”或后台已读标记替代。原已付状态发生在开场前，人工结案是本轮事件，二者不得混写。发现验证缺陷后拒绝重查足以继续怀疑，但疏忽或不负责任的客服仍不能仅凭一句回复被定性为完整犯罪链。

本案处理只在明确的“等待本次答复 / 查看处理结果”动作后推进，界面先说明会推进远汀处理；自由看文件和现实用时不触发结案。玩家可先提出暂停，不用拼阅读速度。若唐雯已明确授权并自行等待，她的动作也应可见，不能让主持人在玩家看另一页时偷偷结案。

本轮不加入解冻费、追加损失、威胁电话或“找到缅北地址”。一项生产服务中维持失效付款证明的行为已经足以改变调查目标；不用连续坏事提高严重性。

## 分支改变什么，而非只改评价

- **直接问顾成：**他可以正常承认外包或误接并停用；公开测试结果不会因解释消失。是否采信误接，取决于后续有没有独立核实付款，不能因他平静或回避判罪。
- **只撤图 / 取消追加咨询：**两项都完成，不再联系追加。过去 3,000 元的争议不自动消失，也不是玩家触发的新损失。
- **先停核验组件：**停止对客生成结果；用隔离预览验证原版本，不需恢复上线取证。暂停不撤销或延误真实资金本身，平台付款主张仍需它提供依据。
- **提前阻止结案：**本次真实保持待核实，缺少人工维持错误依据那层证据；允许以较有限判断结束。
- **拒绝跟客服争论：**可只把自己的发现告诉唐雯、暂停自己组件；唐雯若选择自己申诉，只回传她明确分享的处理，不替玩家自动搜齐所有材料。
- **拒绝整个事件：**关闭通知，继续办公或结束；不强制后续“你害了她”。调查可行不等于每个玩家都必须继续。
- **改口：**“不是所有平台都假，只是这个核验不能作证”收窄主张，不恢复已撤预约或已停组件。恢复客户联系、公开组件、资金异议分别需明确动作和相应权限，不能一句“算了”全重置。
- **漏看广告或原图：**可以直接从真实提款核验进入后半段，少了社群造假的结论，不损失核验实验。
- **漏看金额变化：**暂留延迟 / 误接解释，原页面可重试；不通过主管讲解自动授予发现。

## 非预设顺序纸面检查

以下是作者按信息边界的排演，不是真人结果。原稿的断点固定在 [9ad2706](https://github.com/TedShao/chengchuan-mystery-game/tree/9ad27069d1e97e9c455f32410abdf20e9f41387c)，不能声称这次修订是对旧未投入设定的自然延续。

| 路线 | 实际顺序与所得 | 检查结论 / 不能夸大的地方 |
|---|---|---|
| 直接追问 | 先问顾成用途 → 接受可能误接 → 比较查询两次结果 → 暂停 → 唐雯决定是否提出资金异议 | 主管承认技术问题也没有结束真实款项问题；后续的判断来自功能和实际处置，非台词破绽 |
| 最早阻止 | 首先撤约、要求停图并停组件 → 隔离预览试不同输入 → 读原分享的提款 → 暂停本次结案 | 所有制止有效，不重开服务；只能得出真实提款使用无效组件、钱款仍待核实，不能伪造人工拒绝证据 |
| 拒绝经办 | 不接角色、不代表客户发送 → 自查自己发布组件 → 将结果交唐雯 → 她自己选择是否处理 | 原工作权限够做自查；她可停止也可自行提出异议，不要求玩家放任广告或承担资金权限 |
| 完全拒绝 | 不查、不发、不继续接触 | 正常结束，保留未知；不应承诺该路线也能看全谜底 |
| 跳过前半 | 首屏直接开原核验 → 固定同编号改金额 → 看本组件使用位置 / 暂停反馈 → 资金异议 | 后半自成一条调查，不以识破陈姐作为钥匙；只知功能问题者不能复述全部作者真相 |
| 先暂停、没保存截图 | 停组件后对外页不可用 → 隔离预览当前已发布版本 → 对照唐雯已分享的原结果与发布引用 | 不需重新上线骗人；若她未分享原账户用途，只能证明自有组件是演示，不能判断真实客户使用 |
| 误判后改口 | 初见延迟就断言侵吞 → 自测后改称核验无效 → 请求独立付款依据 | 具体主张可被受理，过度结论撤回；原已发指控留痕，无怒气条、重复质问不增加钱款风险 |
| 不做后续申诉 | 功能反例与公司用途已确认 → 唐雯暂不继续 | 已排除“仅发生在广告”，尚不能排除误接；允许在此结束而不把未测的明知补成事实 |

### 本轮修掉的牵强点

1. 投入与提款从开场说清，撤约取消的是追加咨询；没有把新损失当成拒绝的报复。
2. 不让“页面返回成功”充当假核验证据，必须实际声称逐项比对且同笔给出互斥结果。
3. 不让内容岗操作资金；暂停的是已制作的组件，且预先解释影响。
4. 原组件先停也有正常隔离预览，无需恢复上线或发假消息换线索。
5. 只读反例能排除有效核验，不能独自证明银行未付；误接与知情后处置分别检验。
6. 同事接到明确停发不换号重发，异议被暂停不另造关闭，重复动作不重复事件；私人草稿不进入任何受理链。

本轮结构上补出了“检验业务功能—确认公司交付—观察实际资金处置”的链条，真人是否愿意继续、实验是否容易理解仍待验证。下一步只检验这条链，不扩章；状态见 [PLAN](../PLAN.md)，单一问题见 [H001](../experiments/H001/game-design-hypothesis.json)。
