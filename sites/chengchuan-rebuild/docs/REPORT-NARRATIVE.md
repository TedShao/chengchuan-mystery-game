# 第一章：从岗位回顾到有后果的判断

## 开场

新存档先进入三段工位回顾，而不是直接选一件玩家从未经历过的工作：

1. 林见的处境、运营支持岗位、同组人员各自负责什么。
2. 回看4月19日的普通通知调整，了解要求、操作、交接、反馈分别出现在哪里。可打开真实邮件，再返回回顾页。
3. 5月15日为何整理个人经历，以及个人汇报与次日培训共享材料的不同用途。

回顾只影响教学进度，不补发历史邮件、不授予线索。同样可以跳过、自由探索或重看。已有草稿的旧存档不强迫重走开场；在案例选择处可回看。

## 提交是叙事行为，不是口令验证

| 实际发出的说明 | 收件人反应 | 可继续的事件 |
| --- | --- | --- |
| 陈述本人动作与收到的反馈 | 留作备选讲解内容 | 核对培训引用，决定是否参与讲解 |
| 保留未知结果 | 接受未确认范围 | 向经办人核对历史回复，或带着未知先看培训 |
| 声称由同事经办 | 原经办记录与说法不一致 | 暂由小雨主讲，玩家可预览并发送具体分工片段给同事确认 |
| 只写准备做、否认参与 | 不把计划当个人经历 | 转为旁听，对照已经发生的记录，可稍后补稿 |
| 推断全部解决或依赖汇总结论 | 留为待核候选，不确认真实性 | 核对引用范围，决定是否授权已发稿 |
| 归档时间写得不同 | 要求核对具体通知 | 暂不主讲，向小雨核对归档要求 |
| 意思不清或无关内容 | 暂不能作为个人经历 | 先旁听材料准备，不要求反复填到“通过” |

以上均能进入下一段体验。逐栏核对建议作为可选修改辅助；操作教学在首次真实交稿、收到安排后即可结束。

## 关系变化的边界

纯函数 `ReportPaths.advance` 只消费已发送且实际评阅的版本。编辑、选框、打开材料、预览、取消、重复查看，以及被去重的重复提交，不产生关系成本。

第一次明确有问题的陈述先提醒；此前回信已经产生、同一问题仍作为新版本发出，才逐步积累。第二次质疑，第三次明确告知再犯会暂停；第四次暂停本次汇报、主讲及个人稿引用，并向人事发送安排状态。没有让人事获知私人稿件正文。

可累计的问题限于可解释的同类内容：无关正文、未核实的大范围断言、明示凭发送成功推断结果、未解释的矛盾或通知时间偏差。未知、待确认、表达不清、第一次误判与合理分工争议不直接处罚；有实质改善会打断连续升级。

暂停后可以明确申请补充核对，再发送新的说明，进入谨慎复核而非瞬间完全恢复信任；也可以确认接受“转正暂缓”，形成第一章的不利收束。收束后保留已有记录供查看，不再推进第二天或处理新的发送。不会把一般办公失误直接跳接到犯罪结局。

## 信息范围与幂等

- 小雨先只收到参与安排；她看不到发给周衡的整个汇报。
- 玩家预览核对请求后确认发送，小雨才收到那一段原话。她能复述收到的片段，并按经办范围回答。
- 请求可取消、可暂缓。同版请求重复操作不增发；旧版按钮不处理新版本状态。
- 每版回信保留本版安排，新的改口不倒改旧信。旧存档不追溯处罚或重写历史。

## 验证

`report-paths-domain.test.mjs` 验证分类、升级、未知不受罚、版本幂等和补充核对；`report-narrative.cjs` 通过真实页面检验开场、分工争议、同事知情范围、改口、警告、不利收束、刷新与窄屏。

这是一组第一章可玩的分支。案件最终结局、整部游戏的长期人物关系仍需后续章节独立铺垫，不能由一次表单评分代替。
