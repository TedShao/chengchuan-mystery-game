# 项目基线与开发入口

更新：2026-10-21。当前故事是 **《回来以后再联系》**：招聘助理林见从一通家属来电，追查自己接待过的陈平为何无法回家，以及公司在继续招聘前已经知道什么。

## 当前决定

- 澄川主营本地电商客服招聘，存在真实业务与普通员工；孟宁负责的海外项目为境外诈骗团队招募人员。公司的角色、部门和知情范围只在 STORY 定义。
- 采用境外诈骗与人员受控的作者真相；保留主角因误信同项目、主动申请海外客服而受控的坏结局；他有原售后经历和事前咨询，须另行决定报名、离职和出发，不是招聘助理被派去海外。该线在较早阶段分流，获悉具体受控事实后不再演无知出境，也不能由乱点或激怒同事触发。
- 游戏主体仍是公司电脑内的网页探索、模拟通信与自由办公。日常办公提供环境，调查不以完成工作量或填出标准答案为门槛。
- **已进入工程重构。** 用户于 2026-10-21 授权重构前后端并清除旧 5174 实现；新版运行于同一 5174，使用独立新存档。AI、真实通信与付费服务仍暂缓。
- 旧故事、旧调研、旧实验及旧剧情试玩记录退出当前目录。不得从历史或保留代码中补齐新稿的空白；不确定之处按 PLAN 核实。

## 需要读哪些文档

| 工作 | 唯一依据 | 负责回答 |
|---|---|---|
| 理解项目方向 | 本文 | 做什么、当前边界、哪些已确认 |
| 写故事与人物 | [STORY](design/STORY.md) | 完整梗概、主营业务、人物、作者真相、时序、推论与结局 |
| 写场景与可见材料 | [SLICE](design/SLICE.md) | 开场至结局的场景、具体素材、行动、非预设路线和验证 |
| 设计界面和行为 | [INTERACTION](design/INTERACTION.md) | 操作教学、软件职责、发送与改口、知识边界、反馈和可访问性 |
| 决定下一步 | [PLAN](PLAN.md) | 进度、缺口、优先级和验收 |
| 执行一次迭代 | [WORKFLOW](WORKFLOW.md) | 怎么提问、删改、审稿、验证和提交 |
| 查证现实 | [REFERENCES](research/REFERENCES.md) | 本故事所用来源、支持程度和虚构边界 |
| 找仓库文件 | [DOCUMENTS](DOCUMENTS.md) | 当前资产职责、清理范围 |

故事事实发生冲突时先改 STORY，再同步场景和交互；界面不能反过来创造真相。版本由 Git 管，不新增“最终版”“v5”等平行大纲。新规范不等于已经通过玩家验收。

## 已实现与未实现

`sites/chengchuan-rebuild/` 已整体替换为新招聘故事：序幕、工作通讯、邮件回执、原件与并排材料、公司网站、内网组织关系、自由办公、个人求职与三类结局。新规则集中于 `src/domain/`，本地 Node API 与静态浏览器共享；界面不直接改角色知情。

`feat/recruitment-desktop` 是工程分支，基于 `docs/mystery-rebuild-v4` 的故事基线建立，分别评审。文档中的角色动机与全部话术细节仍需持续验证；当前是可玩重构版，不宣称已完成真人盲测或产品发布。main 与线上 Pages 未合并更新。

工程操作见[在线工作指南](ONLINE-WORKFLOW.md)和[项目运行说明](../sites/chengchuan-rebuild/README.md)。本地 5174 与原 5173 保持隔离；`sources/` 是只读同步材料，不在本仓库清理范围。
