## R01：先推翻“已经有一部值得实现的故事”

**问题证据：**用户反复反馈无聊、像说明书、不知道干什么，最新指出戏剧冲突不足。v4 的日志与本人回复能很快解决取消原因，主管又接受多数合理请求，尚未证明有持续对抗。

**当前结果：**更正后不再要求沈航继续求助。玩家可以从自己已有关联的出席卡，核实公司是否在知道出席者受雇的情况下，仍正式向远汀提供“非工作人员”交流。只撤个人、允许真实员工咨询、要求整单暂停产生不同结果。提前暂停不会被绕开，因此可能阻止也可能失去一项后续证据；不重启退款或付款核验。

**选案交付规则：**退款与其他旧案保留固定 Git 历史，当前只维护新片段。作者检查负责区分事实、动作与后果，不把逻辑可区分直接当成真人愿意继续。

**重写方向约束：**

- 把“我想查公司”落到主角已经参与的一件具体事，不靠突然加工资威胁或绑架倒计时。
- 当事人的联系许可、玩家参与意愿和公开纠正分开；不能无预告惩罚诚实、强迫侵犯隐私，或要求放任误导换线索。
- 主管应有自己的主动行动与可解释的局部让步。揭穿一个借口以后，玩家的目标应发生变化。
- 允许删除罗青、许川或沈念中的角色，改动业务包装，甚至完全放弃“那句谢谢”；保留需说明独有贡献。
- 境内运营与境外业务关系逐层核实；涉及现实机制时按需回到来源，不为谜题现造事实。

**通过 G1：**读者无需看作者真相就能说出一场冲突；至少两种合理行动各有明确且可预见的后果；至少两种解释可以被玩家检验；高潮改变人物目标或关系，而不只是替换一份材料。若两稿都只剩流程错误，全部放弃再选事件，不挑“相对好一点”的去实现。

**结果落点：**直接替换现有 STORY / SLICE 中已退役的核心部分，落选方案只留短比较，细稿不作为并列依据，不另建版本稿。新事件须有可观察的公司行为矛盾和常规权限下的区分动作；不靠把两个品牌先宣称为独立审核，不靠玩家放任错误消息发出才能查下去。

## R02：把故事变成操作，而非让人物讲答案

**决定：**玩家用什么行为证明自己的猜测，界面怎样反馈真实后果。

交付一份 `docs/design/SLICE.md`，涵盖：开场前因、可见材料、调查出口、对象权限、实际发送、知情变化、误判与改口、退出结果。只为片段需要的软件设计交互，不先设计所有办公菜单。

必须排演：先问人不读文件、先读文件不问人、相信权威、拒绝参与、只转部分信息、先公开误判再私下改口、重复操作。人物根据实际接收或有权限下实际查阅形成知识；团队会话不能被误标成永久私密。

**通过 G2：**至少两条不同核实路径都成立；没有指定用词门槛；主要分支改变事件而不只改变评价；选择后可辨认“谁知道了什么、哪件事真的发生”。草稿和收件范围能看懂，删掉可有可无的软件操作。

## R03：先证伪，不急着保住自己的方案

采用 [H001 实验合同](experiments/H001/game-design-hypothesis.json)中的问题边界。R01 若选择另一类冲突，就先修订合同；不能为了适配实验保留被否决的故事。

H001 本轮检验“公司实际卖的角色”能否延续更正后的调查。作者排演已给出局部与公司层的区分条件，但未证明玩家会主动查看交接、理解商业承诺与实际会谈的差别，或想追查购买者的目的。可做完整分场的陌生玩家观察；若仍只想改文案，回 R01/R02，不增加事故或说明性对白。

分两次判断：先由作者做逻辑与边界走查；再请未读剧本的人自由体验分镜或最小原型。不能拿同一人先看答案再重玩当新玩家。比较版本尽量只变一个关键机制；若台词、界面、信息顺序都改了，结论仅限整段可用性，不能声称某一机制造成提升。

**接受证据：**玩家主动提出并尝试验证疑问，能说明至少一个取舍；结尾仍有来自角色处境的下一问题。记录反例与不愿继续的人，不以完成速度、读完比例或“看起来顺畅”替代。

**否决证据：**只挑明显正确选项；只关心任务完成；选择后不知道损害了谁；只能说“主管是坏人”却没有新的问题。此时删掉或回 R01，不继续补背景、发下一任务。

**缺证据：**没有陌生玩家，结论为未定，不标体验通过；准备工作可继续，生产重构不提前扩量。

## R04：工程重构只服务通过的片段

当前技术审查发现：

| 位置 | 实际情况 | 计划动作 |
|---|---|---|
| `web/reply-opening.js` | 开场状态、规则、材料、渲染在同一文件 | 选定片段后才抽取其事件与知识边界；不把旧内容原样搬层就称为重构 |
| `web/report-*.js` 等 | 完整办公仍有规则在前端；相关 domain 测试直接导入它们 | 准确说明现状；只迁移新片段依赖，避免同时重写全应用 |
| `src/domain/*.mjs` | 部分第二天规则供本地服务器与静态打包共用 | 评估可复用的事件处理，不默认其故事数据继续有效 |
| 两个 HTML 入口与多代教学脚本 | 实际存在多种开场体验 | 先保持旧存档安全；试验通过后明确一个生产入口，其余标为历史或移除 |
| 历史测试与近期 CI | 旧脚本环境不统一，不是全都在跑 | 给测试标适用版本；保留行为约束测试，废弃依赖旧剧情措辞的断言 |

**最小工程目标：**一种事件规则来源、按实际接收/查阅派生的角色知识、动作独立反馈、可回退存档策略、兼容 Pages 子路径。具体框架不预选；不为本片段引入后端、AI、外部消息或付费服务。
