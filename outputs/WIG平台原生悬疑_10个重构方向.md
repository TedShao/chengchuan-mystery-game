# WIG 平台原生悬疑：10 个重构方向

日期：2026-10-16

本轮根据用户纠正重新构思。设计起点是“玩家为什么使用这个网站、在里面能做什么”，再建立人物、事件和隐藏真相。前一批从生活事件出发的候选保留作历史记录，不作为本轮默认方案。

这些是可供选择的概念，不是已经完成唯一解验证的大纲。底牌说明创作方向，后续仍要建立完整时间线、人物知识边界与证据关系。悬疑质量继续参照《优秀悬疑故事：多维度标准与 WIG 审稿体系》。

## 共用设计前提

- 整个游戏围绕一个可信的虚构网站或平台展开。需要外链时，只连接少量与主平台有明确关系的虚构页面。
- 玩家先有一个正常身份和办事目标；异常出现在实际操作中，不由陌生人突然发来整套案件资料。
- 栏目、搜索、记录、附件、站内信与权限形成探索空间。普通页面也有正常用途，不能每页都是谜题。
- 推进过程主要是“发现矛盾—提出问题—查找材料—修正判断—作出操作”，并非不断输入下一页密码。
- 人物通过他们本来就会留下的申请、帖子、批注、消息和材料出现。网页是活动场所，不只是案件资料陈列柜。
- 关键角色有自己的知识和目的，不会因为玩家点开一个网页就无理由地知道玩家在调查什么。
- AI、真实邮件和虚拟电话作为演出与交互补充。固定真相、主线证据和通关不依赖实时生成或真实通信成功。

## 01｜《离校手续尚未完成》

**网页主体：大学统一办事大厅，连接学院官网、图书馆和校友站的少量页面。**

### 玩家身份与日常目标

玩家是毕业年级学生，在档案室做最后一段勤工助学，协助核对历史离校材料，同时办理自己的毕业手续。账号能访问分配给自己的待核材料，不能随意查看全校私人档案。

首页很正常：离校进度、欠费提示、毕业照预约、宿舍退还、档案去向、图书归还。校园消息里，同学们正在找工作、卖旧书、准备毕业晚会。

### 第一处异常

你处理的一份十多年前的离校申请，最后一项一直没有签字。档案老师让你先标记为“历史遗留”。当你返回个人页面，却发现那份申请刚刚获得批准，审批时间是今天。

签字人是一名学校已公开悼念过的老师。

### 人物与隐藏真相方向

主要人物包括催进度的辅导员、保管纸质材料的档案老师、正在回校参加活动的知名校友，以及那名在公开介绍里“主动退学”的旧学生。

当年有人替另一名学生取得了毕业资格，相关材料通过姓名、学号和审批归属的局部调整，掩盖了被替换者真正的离校原因。旧审批账号被后来的工作人员沿用；今天的签字是活人处理积压材料留下的痕迹，并非死者复活。

如今学校要进行档案迁移，历史材料之间原本被人为隔开的关联重新出现。主要谜题是两个学生的经历如何被拼成一个人的履历，以及谁仍在维持它。具体身份替换范围须在正式大纲中限定，不能写成能够随意篡改所有外部档案。

### 网页里的推进过程

异常审批编号 → 旧表单的院系代码 → 图书馆存档中的毕业作品 → 作品致谢里的另一位同学 → 学院官网历年名单 → 校友人物介绍与原始经历冲突。

玩家不是破解电脑，而是利用材料之间的引用、旧名称和公开记录逐步识别同一经历的不同归属。档案老师或相关人确认新的问题后，才提供进一步材料权限。

### 主要吸引力与验证点

玩家自己的毕业离校，与一个始终未能真正离校的人形成对应。校园网站可以同时容纳日常、关系和旧事，不必从第一屏就阴森。

**最需验证：**身份与资格替换的具体操作和历史背景；主角能够接触哪些材料；不能用万能管理员权限解释一切。

## 02｜《欢迎入职，离职申请已通过》

**网页主体：公司办公 OA。**

### 玩家身份与日常目标

玩家是新入职的项目助理，通过 OA 完成培训、领取设备、加入部门、阅读交接材料。新人引导、食堂菜单、假期申请和团建投票维持真实的办公气氛。

### 第一处异常

设备还没有领到，系统已经给你生成了一份离职申请。离职日期是下周，附件里还有一份写好了原因、只差确认的交接说明。

人事说是模板残留。可是通讯录里，你的前三任前辈都留下了几乎相同的说明。

### 人物与隐藏真相方向

主要人物是耐心带你的同事、强调流程的项目经理、对旧项目避而不谈的人事，以及看似还在处理工单的前任账号。

一个发生过严重质量问题的项目正在被收尾。管理者利用岗位交接和预填审批，把旧项目的知情、验收和后续处理包装成新一任经办人的工作记录。前任离职文案不是独立证词，而是同一套责任叙述的不同版本。

故事不将“点过确认”夸大成现实中自动承担全部法律责任。危险来自资料呈现、内部指控与事实被混淆；玩家要识别自己被要求确认的究竟是什么。

### 网页里的推进过程

新人待办 → 预填离职附件 → 附件引用的旧项目 → 文件版本记录 → 已停用账号的批注 → 原始会议纪要 → 当前待审批事项。

玩家可以退回有问题的申请、要求补充材料、保留原始版本。管理者只有在收到这些工作动作后才会反应，形成合理的对抗。

### 主要吸引力与验证点

“完成待办”的习惯逐渐变成压力。系统非常礼貌，风险隐藏在正常流程和同事关系中。

**最需验证：**流程应具体可懂，避免全篇术语；提前离职材料必须有真实的管理动机，不能只是为了开场吓人。

## 03｜《三号楼还有人投票》

**网页主体：老小区居民服务平台。**

### 玩家身份与日常目标

玩家回老家替母亲处理物业缴费、维修预约和改造意见征集。经母亲授权操作其住户账号，也能浏览小区公开公告、讨论区、地图和历史公共项目。

### 第一处异常

新地图上已经没有三号楼，但意见征集里仍然出现三号楼住户的反对票。物业解释是旧数据未清理。

随后，一条维修请求请求恢复“每天晚上唯一还能走的通道”，被客服归并成了你母亲家的一张普通照明工单。

### 人物与隐藏真相方向

人物包括爱转发通知的母亲、热心的楼长、长期被视为难缠的老住户，以及忙于交付改造项目的物业负责人。

三号楼并未在现实中凭空消失，而是在用途调整、门牌更名和地图更新中，被统一写成了不再居住的附属空间。仍住在其中的一些人没有被如实纳入当前方案。负责人试图让审批建立在“那里已经无人居住”的错误前提上。

部分居民曾获得实际便利，因此不愿追问旧账；他们有不同程度的知情与动摇，不是全小区集体作恶。

### 网页里的推进过程

投票统计 → 历史楼栋别名 → 同位置的旧维修单 → 门牌变更通知 → 不同版本的小区地图 → 夜间保洁与送货记录 → 受影响住户主动提供的材料。

玩家通过服务记录与空间对应证明“这些编号背后仍有真实生活”，随后才能正确理解那张被归并的工单。

### 主要吸引力与验证点

熟悉的物业页面会逐渐呈现另一张小区地图。玩家最初处理的是缴费和修灯，后来必须判断一张看似有益的改造方案漏掉了谁。

**最需验证：**建筑空间与门牌变化必须自洽；数字记录不能抹去现实人的行动能力；正式权属和处置程序不靠游戏一句话裁决。

## 04｜《家属入口》

**网页主体：疗养机构家属服务平台。**

### 玩家身份与日常目标

玩家为刚入住疗养机构的父亲办理探视、生活用品配送和活动报名。平台展示每日照护照片、餐单、活动安排、家属留言与工作人员回复。

### 第一处异常

父亲每次都在你预约探视之前“自行取消”。留言里还是他一贯的语气：“这里挺好，别来回折腾。”

可是某张标为今天的活动照片中，出现了一棵已经被公告移除的树。

### 人物与隐藏真相方向

父亲固执，不喜欢让孩子担心；熟悉他的护理员回复越来越谨慎；服务主管始终提供完整而礼貌的解释。

机构把一批住户转移到了条件与承诺不符的合作场所，却仍用旧活动素材和预填反馈维持原服务的表象。护理员发现问题后尝试帮助住户与家属联系，但只能接触自己负责的部分人，也担心贸然离职会让他们失去支持。

并不是父亲的所有留言都伪造。他起初确实不愿麻烦孩子，这使后来的替写更容易被相信。核心推理是区分真实的体谅、模板化表达，以及当前真正的生活状况。

### 网页里的推进过程

探视取消记录 → 当日活动照片 → 场地维修公告 → 人员排班变化 → 自己家属的配送地址变更 → 其他家属自愿分享的异常 → 工作人员提供的限定范围转移资料。

不让普通家属账号直接查看所有住户的健康档案。公开服务信息和获得同意的材料足以构成调查空间。

### 主要吸引力与验证点

“别担心我”本来是安慰，随后变成最难判断真假的话。网页里的温暖宣传与细微的不协调可以逐步积累不安。

**最需验证：**常规电话、探视与求助不能被无理由封死；重点是照护与服务记录，不以虚构医学知识作为解题门槛。

## 05｜《这场戏还没结束》

**网页主体：业余剧团排练与演出管理平台，连接公开售票页。**

### 玩家身份与日常目标

玩家是新加入剧团的制作助理，准备一场经典剧目的周年复排。需要核对演员档期、道具借用、台词版本、场次安排和观众反馈。

### 第一处异常

后台有两份都标为“首演最终版”的剧本。一个版本里有求救台词，另一个没有。导演要求使用较新的那份，却坚持它从未被修改过。

当年的评论里，有观众特别称赞这一段“演得像真的”。

### 人物与隐藏真相方向

人物包括希望重获认可的导演、当年的替补演员、说话很少的舞台工作人员，以及这次复排的主要发起人。

当年演出中出现过真实的紧急情况。事后有人修改剧本与演出说明，使一段实际求助在公共记忆中变成既定表演，掩盖自己对危险的知情与处理失当。

复排发起人希望让当年的不同见证者重新面对彼此的记录，但其公开揭露方式也可能伤害未同意参与的幸存者。玩家不只要查出版本差异，还要决定如何使用真相。

### 网页里的推进过程

剧本批注 → 道具与音效的实际出场顺序 → 排练日历 → 替补名单 → 售票场次 → 首演前后的观众评论 → 不同来源的录音及完整文字转录。

谜题主要是版本、顺序与人物所处位置，而非冷僻戏剧知识。

### 主要吸引力与验证点

同一句话，在剧本里是台词，在真实记录里却是求救。玩家越理解舞台流程，越能看见被“精彩演出”遮住的事情。

**最需验证：**舞台和观众视角要画图验证，不能让全场无理由地忽略明显危险；音频线索须有可访问的文字等价材料。

## 06｜《请勿办理退房》

**网页主体：老旅馆预订与值班后台。**

### 玩家身份与日常目标

玩家接受了一份远程整理历史住宿账目的临时工作。旅馆准备重新开业，要求先在旧后台完成一轮培训：核对预订、安排房间、处理留言和结清历史账目。

### 第一处异常

你在标为历史快照的房态表中调整了一间房，立即收到客人的新留言：“我们还没有走，为什么把房间卖给别人？”

查询公开资料后发现，这批客人住店的那一晚，旅馆发生过事故。

### 人物与隐藏真相方向

这是明确采用真实灵异的候选。旧后台只连接那一晚曾经留在旅馆中的人和他们当时知道的事情；不会提供未来知识、万能答案或任意预言。

住客和夜班人员的叙述不断重复，但不完全一致。他们对“谁离开过旅馆”“谁在替别人办手续”的理解各自有限。正式登记册漏掉了一名随员工住店的孩子，导致后来对现场人数与救助经过的还原存在关键缺口。

这个孩子后来活了下来。玩家最终要确认的，不只是遇难者的身份，也包括一个仍活着的人为何一直不知道是谁把自己送出去。

### 网页里的推进过程

房态表 → 加床和餐食数量 → 前台留言 → 员工交班本 → 房间维修停用记录 → 当年公开报道 → 重新核对每个人的去向。

点击退房只是整理记录，不能靠随意选项“杀死”住客。随着关键事实确认，可见的历史片段逐步完整，灵异规则保持稳定。

### 主要吸引力与验证点

同一个后台同时具有工作界面和叙事空间的作用。房间、姓名和入住状态都有双重意义，少量界面就能形成封闭空间感。

**最需验证：**灵异规律及其触发条件必须先建立；不让任何鬼魂突然知道全案；历史整理与真实事件的边界需让玩家理解。

## 07｜《族谱正在修订》

**网页主体：家族线上族谱与纪念馆。**

### 玩家身份与日常目标

家族准备修缮祠堂，玩家受托校对电子族谱。要录入旧照片、确认亲属关系、合并重复人物，并为长辈上传口述材料。

### 第一处异常

系统建议合并几位“资料相同”的女性。你同意处理后，一位年迈亲属留言：“她们不是同一个人。”

几份原始手稿里，孩子与母亲的关系，和当前族谱显示的不同。

### 人物与隐藏真相方向

人物包括热心主持修谱的长辈、很少参与家族活动的姨婆、负责纪念馆文案的年轻亲属，以及被赞颂为“收养孤儿”的先祖。

家族流传的救孤故事，隐去了部分孩子当时并非没有母亲，以及女性如何被迫与孩子分离的经历。后来的修谱进一步把不同人的名字、称谓和关系压缩成服务于家族声望的版本。

当下并非人人知情。有人真心相信祖辈善行，有人担心揭开事实会毁掉亲人的认同；玩家需要分辨资料错误、历史有意改写与后代的善意误解。

### 网页里的推进过程

人物合并建议 → 姓名与称谓别名 → 手稿页边批注 → 同时期照片 → 祭祀和寄信记录 → 不同家庭保留的口述 → 关系图重建。

所有合并可撤回，原始资料保留。玩家的主要操作会实际改变关系图，却不能把不确定的关系强行判为唯一答案。

### 主要吸引力与验证点

普通“整理重复数据”的动作，可能再一次让一个人的名字消失。恐惧与悬疑来自家族共同叙述里的空白，不依赖血字和吓人动画。

**最需验证：**历史背景与亲属关系必须具体；不能用现代想象随意概括旧制度。若选择真实年代，需要进一步查证。

## 08｜《停服公告》

**网页主体：一款童年网游的官网、玩家论坛与账号中心，不制作网游本体。**

### 玩家身份与日常目标

游戏宣布停服，玩家回来找回旧账号，下载截图、留言和好友资料。官网仍挂着旧版本公告、活动获奖名单、公会招募和多年前的客服回复。

### 第一处异常

你看到一篇以自己旧账号发布的线下聚会邀请。你记得那个活动，也记得一位朋友之后失联，但从未发布过这篇帖子。

帖子不是后台凭空伪造：当年你曾把账号交给公会会长代管。

### 人物与隐藏真相方向

人物包括当年照顾大家的会长、习惯潜水的老朋友、准备停服的现任维护者，以及失联者留下的多个角色账号。

会长利用代管权限和自己的论坛管理权，借不同成员的可信身份组织活动。失联者曾发现某些现实交易的问题，并试图通过活动核实；之后发生的事情被写成“卷走公会钱后退游”。

当前维护者只是按计划停服，不是全知反派。调查窗口来自资料即将归档，证据来源包括独立玩家保留的内容；失联经过和具体犯罪需要后续确定，不能仅凭代发帖子定案。

### 网页里的推进过程

账号恢复 → 自己的历史发帖 → 活动版本差异 → 公会角色昵称更名 → 客服申诉 → 其他成员自愿共享的站内信 → 邀请与现实时间的对应。

虚构游戏的规则会影响玩家如何理解“在线”“出席”“持有物品”，但规则通过官网教程自然提供，不要求用户有特定网游经验。

### 主要吸引力与验证点

怀旧网站天然允许自由探索，梗、旧头像和攻略可以同时建立人物与年代感。核心是重新认识曾经信赖的网络关系。

**最需验证：**停服倒计时按剧情推进，可暂停；明确哪些记录归谁控制，不把所有数字证据都写成随意篡改。

## 09｜《婚礼筹备中》

**网页主体：婚礼协作平台。**

### 玩家身份与日常目标

玩家是新娘的手足，被邀请担任婚礼统筹。平台里有宾客确认、座位图、婚礼流程、供应商订单、相册、音乐清单和双方家庭留言。

### 第一处异常

几位看似互不相识的来宾，对同一张老照片表现出强烈反应。每当你调整座位，他们又被另一个协作者放回同一桌。

新郎很在意一段不属于婚礼的旧视频，甚至愿意为它取消重要的仪式环节。

### 人物与隐藏真相方向

新郎与新娘一家有一段没有坦白的历史联系。他想借这场婚礼，让涉及一桩旧事的亲属、故交同时出席，利用公开播放的材料迫使他们面对过去。

他有真实的受害经历，但掌握的解释并不完整。新娘发现部分计划后，没有简单配合或一走了之，而是在确认事实、保护家人和面对被利用的关系之间挣扎。

玩家开始以为需要找出破坏婚礼的人，后来要阻止一场建立在不完整证据上的公开审判，同时让被掩盖的真实问题得到面对。

### 网页里的推进过程

座位图的修改记录 → 宾客自填关系 → 旧相册 → 视频素材的剪辑版本 → 双方家庭留言 → 新郎准备公开的叙述与原始材料对照。

新郎选择婚礼是因为这些人确有亲友关系、能够自然到场，不靠雇来一屋演员或全员参与阴谋。

### 主要吸引力与验证点

每一个普通筹备动作都可能改变人物相遇的方式。网页权限由谁授予、谁修改过什么，本身就是关系的一部分。

**最需验证：**新郎为何采用如此昂贵且伤害关系的方式，需要有充分性格和历史依据；不能把婚礼仅仅用作强行聚齐嫌疑人的道具。

## 10｜《直播尚未结束》

**网页主体：地方网络电台的节目制作与听众服务平台。**

### 玩家身份与日常目标

玩家是新来的节目编辑，为一档周年特别节目整理素材。任务包括制作字幕、核对播出时间、筛选留言、填写音乐版权信息和编排节目单。

### 第一处异常

你整理的是十年前一场广受赞誉的“直播救援”。公开版里，主播及时接通电话并帮助了一名求助者。

后台历史来电队列却显示：那通电话一直没有被接入直播。

### 人物与隐藏真相方向

主要人物是当地很受欢迎的主持人、当年的导播、为这场直播写过报道的记者，以及求助者的家属。

公开节目把真实发生过的电话、事后重录的话语和其他时段的声音拼成了一场及时救助。真正首先采取行动的人被从故事中删去，主持人则获得了持续多年的声望。

重点不只是“节目造假”，而是当时谁知道求助、谁作出选择，以及一个被传播得极其完整的英雄故事如何覆盖了真实经历。

### 网页里的推进过程

字幕任务 → 来电队列状态 → 音乐与广告的实际播出日志 → 未剪辑素材 → 导播批注 → 首版新闻 → 当事人提供的独立时间记录。

来电队列只是疑点，不能单靠“系统显示未接通”定案；独立录音、时间及人物行动共同验证。全部音频提供同步文字和清楚的时间标记，不要求辨认极微弱声音。

### 主要吸引力与验证点

玩家亲手编辑、对齐的声音逐渐推翻自己原本准备制作的纪念节目。同一句温暖的话，在知道它何时录下后，会变成另一种东西。

**最需验证：**播出、录制、转录与补录时间需严格区分；不能过度依赖专业广播知识，制作工具必须容易理解。

## 本轮推荐

**最符合“自然在网页里摸索”的主方向：01 校园办事大厅、02 办公 OA、08 旧网游官网。**三者都有大量天然栏目、权限差异与正常内容，可以在不强迫玩家按单线阅读的情况下容纳探索。

**最适合做风格鲜明的短篇验证：05 剧团平台、06 旅馆后台、10 电台平台。**它们的主空间更集中，谜题操作与主题关系清楚。

这只是平台适配与制作形态判断，不代表故事已经优于其他候选。选定后应先制作一个完整探索片段，检验玩家能否从具体矛盾自然提出下一次搜索，而不是依赖作者不断发来提示。
