# 故事规范：这单是我下的

状态：2026-10-21。在 [41cb9bf](https://github.com/TedShao/chengchuan-mystery-game/tree/41cb9bf0014a6757922095a36ea82aa4a2e86df7) 上比较两个业务事件并作作者纸面验证，选用跨境托管店方案，替换《替你说的话》。不沿用独立交流、换人、身份卡或交付审批。人物姓名可复用，旧事件和知识不继承。未改代码；操作与反路线见 [SLICE](SLICE.md)。

## 先把生意说清楚

| 对象 | 对外业务、付费与承诺 | 作者固定的实际业务 |
|---|---|---|
| 知禾 | 网店入门课程，教授上架、接单、回复和基础运营 | 提供入门入口；不能仅因课程导流便认定每位讲师知情 |
| 澄川 | 知禾的课程运营与远汀的商户入门协作方；收项目方的运营服务费 | 做课程支持、商品页面、样店演示和商户交接。核心项目人员知道部分样单被用于正式店铺的收款过程；普通岗位只见自己一段 |
| 远汀 | 自营跨境店铺托管平台：学员付开店服务费取得自己的商户账户；平台声称引入海外买家、托管买家货款；商户逐单支付采购成本，由平台供货发货，签收后回款 | 本案经营者控制店铺、订单显示、采购要求和客服，制造没有真实买家付款的订单，向商户收取所谓采购款；主要收入来自商户投入，不是把商品卖给海外消费者 |
| 沈航 | 刚付过开店服务费，开通正式店铺；开场收到第一笔订单的采购要求，尚未支付该笔采购款 | 他不是新追加的受害者；既有开店和这笔待采购贯穿全段，不在后半突然加损失 |
| 林见 | 入职第 47 天的课程运营，准备商品页和课堂样店，答学习问题 | 昨天按工作要求在样店生成一笔不扣款、不发货的演示订单，今天才第一次接触该对象在正式商户端的用途 |

这里“买家”是声称购买商品的人，“商户”是沈航，“项目客户”是付澄川服务费的远汀；三者不混叫客户。教学中生成样单本身合理，跨境与代发货也不等于犯罪。

**本片段要证明的范围：**一笔没有买家付款、可追溯到林见教学操作的订单，被远汀用于向真实商户索取采购资金；在实际核对来源后，对应资金要求仍被维持。不是检查广告是否夸张，也不要求本段证明所有订单、全部员工或整个资金网络有罪。

## 两个候选及选择

| 比较项 | A《这单是我下的》：跨境托管店 | B《谁能把它带走》：设备托管出租 |
|---|---|---|
| 生意 | 远汀向商户卖开店与履约服务，商户逐单垫采购款 | 远汀向个人售出指定相机并代出租，收购置款和管理费，承诺本人可取走自己的设备 |
| 核心矛盾 | 我的未付款样单，成了他必须采购的已付款订单 | 同一台标明独占所有的设备，两个已有客户都能申请取走 |
| 开场钩子 | 学员订单上的买家留言，是我昨天随手写的收件备注 | 客户想取回设备，另一份已存在的取货预约指向同一序列号 |
| 行动验证 | 经订单内联系到自己的买家端，直接回应、撤回；核对对应商户采购项是否撤掉 | 各自授权取货，比较仓库实际交付；只有网上两次预约不够 |
| 普通解释 | 样单复制或环境串接；需核对同一活动会话及正式收款用途，不能看备注就定罪 | 共用图片、设备池、编号错、二次分配或共同所有；需排除契约和实物问题 |
| 直接追问 | 孟宁可说是样单，远汀可说是店铺订单；玩家握有买家端，不依赖承认 | 一句“仓库标签串了”仍能解释，需实物核对才进展 |
| 提前阻止 | 停催办和不支付有效，已存在的订单与采购要求仍可核实 | 停止交付有效，但主要反证要等待实物交付，与提前阻止有张力 |
| 拒绝参与 | 不做新样单、不接项目，仍能查看自己昨天的买家操作 | 退出交接后常只剩找人提供证书、合同或仓储凭证 |
| 网页与规模 | 两个角色视角、同一订单、已有两个人；十分钟片段可容纳，时长待测 | 在纯网页中难验证相机实物；容易增加仓管、第二业主与物流等待 |

**选 A，退 B。** A 的关键优势是玩家持有交易的另一端，而不是更坏的罪名或更大金额。B 可以发展为较长故事，但此处会重新依赖凭证和外部权威。两案都是本轮虚构候选，不把 B 的经营结构当已考证的现实案件。

## 核心故事与转折

沈航发来自己店铺订单，问买家备注是什么意思。里面那句“放前台，不要打电话”，与林见昨天给演示用台灯写的备注一致。单看这点可以是模板复用。林见打开自己的样单，它明确没有付款，也没有安排货物；沈航的正式店铺却显示“买家已付款，待商户采购”。

沈航可以从这笔订单正常联系买家，消息却进入林见自己的样单收件箱。林见可以直接回复事实，而不是输入作者规定的暗号。双向回应让两个人确认这不是仅复制了一张图片：当前商户订单仍连着这个演示买家。林见撤回自己的订单后，演示端真实结束，沈航也看得到买家撤回；但同一订单的采购项和关店前处理要求没有消失。

到此仍可能是两个系统未同步。玩家与沈航可以实际要求远汀撤销这一笔没有买家付款的采购要求。远汀客服在**确实收到并核对本单的样单来源和撤回结果**后，将该采购项复核结果定为继续处理；操作记录只显示本次自己提交的事项，不开放全公司后台。它一边接受演示端已撤，一边仍要求商户完成这笔采购再关店。

玩家由“我是不是弄错了教学数据”走到“我的演示为什么会成为别人要付钱的理由”。**撤掉一份演示不等于解除用它建立的收款要求。** 这不是要求停止失效：林见不再制造或代发样单，沈航也不再付款；玩家无法凭课程员工权限替远汀删除账项。采购项是远汀的要求，不由游戏宣判为沈航合法欠债。

最后的未决问题具体而有限：**这笔所谓买家货款没有支付过，远汀声称托管的到底是什么；澄川交付的演示，究竟在什么时候变成了正式经营数据？** 玩家已经能阻止本次补款，并可把两端事实告诉沈航、撤回自己给出的错误保证。下一阶段需设计对这条交接与货款声称的进一步核实，不用一个境外 IP 直接宣布园区真相。

## 为什么这样发生，而不是巧合掉落证据

昨日样店是为沈航这一批入门商户准备的，林见负责其中的演示订单。远汀在开通商户账户时把同一对象包装为首单，不是真有一名海外买家恰好写了同样的话。样店工具和商户工具共用订单会话关联；项目方通常由协作席继续扮演买家，但林见仍能访问自己生成的样单会话。这是交接与权限隔离留下的口子，不需要破解、服务器崩溃或偷管理员密码。

沈航不是随机找到林见：课程期间就是他解释过这款商品和收件备注，首单有疑问自然回来问。林见前 46 天主要做演示与课程支持，看到的完成量不含商户收款状态；本次真实商户反馈跨过了岗位信息边界。不能让他长期操作完整催款链，还声称什么都不知道。

孟宁知道演示来源，收到商户矛盾后可以停本组催办、撤课程侧演示，并把本笔问题转远汀；她没有权直接撤远汀的商户采购项。作者真相中她知道样单被用于制造商户首单，但玩家不能仅凭职位或她停不了远汀就推出这一知情。她的局部让步是减少眼前冲突并保住交接业务，不会长篇讲犯罪规则。

## 现实依据与虚构边界

2026-10-21 核读的[江苏省公安厅 2025-02-13 提示](https://gat.jiangsu.gov.cn/art/2025/2/13/art_89956_11491354.html)描述了虚假跨境电商平台以所谓买家付款、采购成本和回款为理由让商户投入资金，以及操控订单的情形。本稿据此选择业务外壳，不照搬真实受害者。

[长青街派出所于 2026-02-01 发布的提示](https://www.dxh.gov.cn/XWZX/XWYS/202602/t20260206_2725401.shtml)也涉及假跨境平台、虚假订单与垫付货款。两份来源**没有证明“课堂样单被转成商户订单”或本文双端消息机制**，这些是明确的虚构设计。作者固定远汀核心运营在境外、澄川为境内协作方，但本段玩家尚未证实具体地点，不以服务器或货币显示代替调查。
