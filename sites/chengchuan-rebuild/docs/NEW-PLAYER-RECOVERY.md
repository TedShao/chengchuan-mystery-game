# 第一章：关闭指引、误判与改口试玩

本轮仅修改 5174 独立项目。使用临时浏览器存档，不读取或重置玩家当前进度。这里是代理模拟的新玩家路线，不等同于真实玩家样本研究。

## 实际走法

序幕 → 关闭操作指引 → 岗位回顾与自己的工作记录 → 选图表整理 → 将制作归给同事、结果保留未知 → 收到主管质疑 → 向小雨核对片段 → 追问旁听及其原因 → 改口重交，但仍不主讲 → 读培训共享页 → 先看服务工作簿 → 误把三个“已处理”理解成用户重复纠缠 → 询问状态含义 → 取转交记录 → 看回访表 → 最后打开原邮件历史 → 比较感谢语日期与新来信 → 提出更正、明确附送原件 → 保留小雨跟进分工 → 读更正后的服务范围来信 → 下班保存。

这条路线不要求先选课程附件，不要求个人稿全部确认，也不要求接手客户。问题来自实际看到的内容，允许先误解再核实。

## 发现与修复

1. “图表是同事整理的，我没有参与”原先被计为本人完成。补上宾语在前的主体识别；图表背景材料改为自己的交付记录，不再把别人的案例文字当成图表原件。
2. 图表分工核对原先可能得到附件补发的固定话术。按工作类型分别回应，无法代答的验收由实际收件人确认。
3. 旁听、记不清、改口、收到哪一版等问题缺乏上下文。新增有限的对话上下文层，分别读取主管持有的报告版本、小雨实际收到的参与通知与核对片段；省略追问可接续当前话题。
4. 同事只在收到实际通知后更新参与认识。由旁听恢复候选会收到新的安排，原本不主讲的决定仍保留，不自动替玩家答应讲解。旧存档只从已有通知恢复记忆，不补发虚构往来。
5. “罗青找我们做什么”误触发个人汇报，“先别讲转正”仍回答转正。区分客户服务、费用和个人汇报，排除被明确否定的话题；追问收款不再重复上一条服务介绍，也不凭服务记录断言资金归属。
6. “这份写的解决是谁确认的”无法衔接案例页。允许询问材料编写与确认责任，但不直接替玩家解释全部矛盾。
7. 只读过原件、没有收藏时无法在更正窗口附送。附件窗口增加已打开的原件，全部默认不选；取消不发送，重开保留说明，实际发送才让收件人获得原件。列表逐项显示，避免勾选项挤成一段。

## 推进动机与边界

旁听不意味着培训材料不再描述玩家经手的工作。参与通知提醒实际待用页仍然存在，玩家可以核对自己的部分而无需替整页结论背书。材料中的范围、日期和状态矛盾仍由工作簿、回访表和邮件承载，不新增“此处有问题”的答案提示。

更正个人汇报、修改共享复盘、授权培训引用、是否主讲和是否接手客户仍是独立操作。聊天只解释，不自动完成这些决定。

- 全部领域测试 45 项通过；下拉、动态教学、第一章及警告/恢复/结局浏览器回归通过。
