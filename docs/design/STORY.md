# 故事规范：替你说的话

状态：2026-10-21。对 [bd1d22f](https://github.com/TedShao/chengchuan-mystery-game/tree/bd1d22f95ba76d209841a5e614ffec99644a94ca) 作无指引作者纸面复查后修订。**局部伪装可识别，但公司调查尚缺推进：更正与停止后可以合理结束。** 本轮精简身份操作与机械回应，撤回“查同学分类即可承接公司调查”的判断；不改代码。具体路线见 [SLICE](SLICE.md)。

## 核心事件与取舍

沈航来找“昨晚那个做过项目的同学”。玩家打开原对话，看到的是自己负责的课程服务席“小林”；可以直接回复或先问顾成，不必经过转接手续。昨晚顾成获准代班，这本来正常；异常是该席向沈航明确说过“我不在澄川上班”，并以普通参与者的亲身经历推荐远汀。

玩家可直接用员工身份回复，发送动作同时接管该对话；也可先停代发而不回复。员工身份本身只让沈航知道现在是谁接待；只有他实际获知昨晚也由澄川员工回答，才会发现先前信任的独立关系不存在。原会话里有他主动询问雇佣关系、坐席针对性否认的往返；不是一张名字填错的卡，也不是未发出的练习稿。

**不修补旧代付案。** 旧事实无法排除代付加称呼错误，本案不声称后来证明那笔钱有罪。退役唐雯、银行尾号、退款截图、撤图任务和联合对账；只保留林见、沈航、顾成与公司电脑环境。没有新受害者、新损失或新凭证。

这也不是“一个人有两个身份就有罪”：课程客服代班、品牌昵称和代运营都可以正常。区分点是**实际受雇的操作者，在真实客户明确询问该关系后，继续将自己表述为无雇佣关系的独立参与者**。游戏只证明这次商业介绍中的有意伪装，不据此宣布整个投资项目诈骗。

## 公司、岗位与个人动机

澄川对外承接知禾课程的社群服务，为远汀提供项目咨询转介。通知、资料、预约和普通客服是真实工作。林见失业三个月后入职，第 47 天，从未投资远汀；他知道团队在下班后会代管服务席，不知道项目组把其中一些席位包装为“热心同学”。本组并非所有普通员工都知情。

知禾是入口品牌，远汀是付费委托方。作者原计划让公司向远汀出售假独立推荐，但本片段只证明顾成这一次伪装。**“顾成个人越界”和“公司批准、持续交付这种服务”都与当前材料相容。** 不要求在本片段证明全公司有罪，但至少应有一个后续动作在两种解释下产生不同结果。当前谁批准、是否普遍、如何收费没有被设计成可验证的冲突；“同学交流”分类与远汀项目归属不能替代这些事实。本轮不把作者计划写成玩家已发现的业务，不根据公司名称推断境外地点。

顾成安排代班，是为了接住沈航主动提出的“想问问真正做过的人”。他没有创造一个无缘无故自曝的角色：现成席位有课程联系历史，转接省事，品牌昵称也便于延续信任。对外头像取自林见自己的入职照，原卡用小林的本人介绍，玩家认得；不是替某个另行授权的真实学员管理其个人账号。他的失误是沈航要再次找同一个人，次日课程值班人林见能按原接待接回。这是一次复访撞上不同操作者，非服务器故障或秘密文件掉落。

林见的切身问题是：“我接回去后，是继续当那个不存在的推荐者，还是告诉他昨晚是谁在说话？”停掉代发能停止自己的参与，却不能让沈航自动知道昨天的推荐来自公司。这足以支持更正眼前的误导；更正送达、代发停止之后，这个理由便可能耗尽。担心自己的头像被再用可以是个人动机，但没有具体差异结果，不能把这份担心写成已成立的公司谜题。

## 表三：线索与行动验证

| 可见对象 | 初读解释 | 实际行动 / 重新理解 |
|---|---|---|
| “找昨晚那个人”的请求 | 普通复访 | 打开原会话、转接原席或直接问顾成；原席竟归自己负责，产生个人问题而非自动定罪 |
| 本席旧名片与“同学交流”分类 | 昵称或常见社群接待分类 | 可说明为何产生身份疑问，不能证明公司有伪装制度；不设按分类检索的下一关 |
| 原对话中“是不是公司的人”的问答 | 若当独立同学看，是正常建立信任 | 员工身份已明确后，针对雇佣关系的否认与事实冲突；不靠昵称推定 |
| 原回复的操作者信息 | 正常服务台的代班出处 | 普通“消息详情”显示本组顾成实际发送；与其“我接的班”相容，不要求破解日志 |
| 沈航收到员工回复 | 可能以为只是换了客服 | 问是否换人；仅在知晓昨夜操作者后回应那句否认，收到完整更正后允许直接结束，不反复问同一道问题 |

推理链：**该会话实际收到无雇佣关系的明确陈述 → 该回复由澄川的在岗员工针对问题发出 → 操作者知道自己的雇佣关系 → 此处存在有意伪装。** 单独接管一个账号、发现代班或改变名片都不够；这三项不能偷换成同一个证据。

## 表四：两种解释怎样被区分

| 解释 | 可预期、可观察的结果 | 本案能收窄到哪里 |
|---|---|---|
| 正常代班 / 昵称填错 | 换真实身份后，旧内容仍是员工能够诚实提供的服务；若过去身份被问过，应说明公司关系或未作否认 | 仅“原席是我的”时仍成立；遇到已发送的明确关系否认才被排除 |
| 同事讲自己的投资经历 | 获利经历可能不是林见本人的，不能凭林见没投资就否定全部 | 即使经历真实，顾成受雇却否认雇佣关系仍矛盾；不查银行凭证救场 |
| 给真实独立学员代运营 | 应有被明确指代的独立本人，消息不能冒充操作者自己独立于公司 | 本席对外是林见本人的头像与介绍，无另一个被代理的学员；顾成直接承接“你是不是公司的人”的第一人称问答；不将任何代写一概视为欺骗 |
| 课程演练或误发模板 | 只能在演练环境或作为明确示例被理解；一条孤立误发不够判断意图 | 沈航真实会话中的连续追问、操作者有针对性的回答及次日复访排除单条称呼/模板错误；不靠截图外观 |
| 公司项目必为资金骗局 | 本片段需有资金去向或投资履行的独立事实才可判断 | 未获得，不能宣称已破整个案件或已定位境外园区 |

拒绝承认雇佣关系的**内容**承担证明作用，实际回复承担改变对方认知的作用；若只为判断过去那句否认，读原文和操作者已足够，无须额外接管测试。不是设计一个“点击按钮就检测犯罪”的软件测试。
